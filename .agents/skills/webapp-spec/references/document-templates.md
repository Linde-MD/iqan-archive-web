# 文档模板

模板是结构参考，不是固定产品方案。替换占位符，不把占位符当事实；已有文档保留其结构。简单产品可合并章节，复杂产品按功能拆分。链接示例仅在目标文件实际生成后保留。

## 根目录 AGENTS.md

```markdown
# 项目实施约定

## 阅读入口
- 仓库通用约束：[开发规范](.github/copilot-instructions.md)。
- 视觉基线：[DESIGN.md](DESIGN.md)。
- 产品范围、阶段与状态：[SPEC 索引](specs/README.md)。

## 产品特有约束
- <已确认的目标、运行环境、数据流边界与明确不做事项>
- <适用的领域正确性要求；不复制通用规范>

## 架构边界
- <沿用的技术栈与已确认决策；尚未实施的能力不称为已有>
- <领域逻辑、UI、文件/存储访问的职责与关键边界>

## Skills 使用
- 使用 webapp-spec 生成或补充规范；该工作流不实现业务代码。
- <实际可用且匹配任务的技能及相对于仓库的入口>
- UI 规划先遵循设计基线，再用匹配技能补充，不覆盖品牌约束。

## 分阶段实施
- 从索引选择规格可实施且真实前置条件已满足的阶段。
- 实施前阅读对应 SPEC；仅完成其范围，不顺带实现可选增强。
- 遇到阻塞问题先确认；范围或接口变化先同步规范。
- 用仓库实际工具验证，按 SPEC 记录验收证据；不把未执行检查标为通过。
```

只链接存在的入口；缺失规范写到索引的缺口清单。已有根指令应合并而非覆盖。

```markdown
## 执行指令示例
> 阅读根 AGENTS.md、此索引及 <实际 SPEC 链接>，确认该阶段可实施且前置依赖已满足；只实施本阶段，使用现有工具验证对应验收项，回填真实结果与剩余问题，不执行 Git 提交。

> 使用 webapp-spec 更新规范：本次新增/修订……；依据材料……，同步受影响需求、阶段、接口和验收项，保留其他内容。

## 变更记录
| 版本/日期 | 变更来源 | 新增/修改/取消 | 受影响 ID | 复核或迁移要求 |
| --- | --- | --- | --- | --- |
| <实际版本或日期> | <本次需求或材料> | <实质变化> | <稳定 ID> | <无则说明> |
```

台账只记录与产品相关的内容；框架中尚不清楚的部分引用问题 ID，不灌入泛化需求。无需为每次调用制造版本号或空变更记录。

框架模式允许接口、任务和验收尚未细化，但必须写出已知内容、缺口、对应问题和补全条件；有核心未决项时不得标为“可实施”。增量更新保留既有验收记录，对变化部分标记复核，不自动覆盖为通过。

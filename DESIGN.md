# IQAN Archive design system

## Direction

Use a dark, data-dense engineering workspace for project archives and version graphs. Build hierarchy with a deep navy canvas, distinct raised panels, restrained blue accents, and compact labels. Keep the interface technical and calm: no marketing-page hero layout, decorative neon glow, or brand assets from unrelated products.

## Typography

- UI and Chinese content: `"Segoe UI", "Microsoft YaHei", system-ui, sans-serif`.
- Version numbers and paths: platform monospace fonts with a readable Chinese fallback.
- Use compact, clearly grouped headings and labels. Do not fetch external fonts at runtime.
- When a task has an external ID, show the raw ID before its name (for example, `20 · Task name`), without a redundant `Task ID` prefix in task references. Use a high-contrast monospace badge for the ID and readable text for the task name; keep the label understandable without color alone. Omit the ID badge when no ID is assigned.

## Layout and components

- Task management offers a board and a compact work-item table, using the same dark surfaces. Size the ID column for at least six digits or the longest project ID, keep columns stable when expanding tasks, preserve unbroken IDs and dates, and allow local horizontal scrolling when needed. Use labeled, keyboard-operable expand buttons for hierarchy; retain full task names and text status cues.
- In project task management, place “全部任务 / 我负责的任务” above the view selector. Show the selected scope with a visible underline and pressed semantics; keep both controls at least 44px tall and allow wrapping on small screens. Preserve the selected board/list layout and search when changing scope.
- In each board lane, keep a quiet plus-and-label add action fixed at the visible bottom, including empty and long lanes. Expand a compact, keyboard-operable form for the task name only, with small visual confirm/cancel controls and at least 44px interaction targets; assign the task ID automatically. Cards scroll independently and the footer scrolls if its form exceeds available height.
- Task details use a quiet header with editable ID and parent task, a separate title and a compact row of icon-led status, assignee, and date fields. Show account avatars with stable initials/colors when no uploaded image exists; make assignee removal available on hover, keyboard focus, and touch. Use distinct status icons alongside readable status text, including in cards and the work-item list. Underlined tabs switch task information and subtasks; the side panel switches comments and linked versions without discarding drafts. Keep feedback unobtrusive but explicit, and stack the main content and side panel on narrow screens.
- Keep the project list as a persistent desktop rail beside the active file or graph workspace; stack regions on narrow screens.
- Present one global archive-root control for browser directory authorization. Derive separate engineering and document directories per project; keep each scan project-scoped. JSON backup import/export uses the shared root directly when configured and offers manual file selection otherwise; handles and paths stay out of JSON.
- Provide a labeled backend-host action in the top bar. Use a dark native dialog for device-name management and unique-host discovery on fixed HTTP 80, separate save/test actions and explicit live status. Preserve field errors and drafts, focus the input on open and restore the trigger on close; allow Escape and narrow-screen internal scrolling. Connection testing selects an address but does not log in or synchronize projects.
- Put the signed-in user's avatar at the top-right. Use the last two Han characters for Han-only names and the first two Unicode characters otherwise; use the uploaded PNG when available. Assign a stable pseudo-random color theme from the account ID, with tested high-contrast backgrounds and foregrounds; do not tint uploaded photos. The avatar menu links to routed account pages for profile, password/security, administrator-only member management, and collaboration/sync, with login for signed-out users and a separate logout action. Keep the existing dark engineering-console surfaces, keyboard-visible focus, and clear text status.
- Render account pages as a focused full-page workspace with a persistent account-section navigation and a clear return-to-workspace action. Keep login, remembered sessions, profile/avatar changes, password changes, admin-only member management, and explicit draft synchronization in their appropriate sections. Allow paste/password managers with correct autocomplete, labeled fields, and focused error feedback. Show shared/cached/legacy-read-only state and pending counts in text; mark unpublished graph rows “待同步”. Preserve conflicted drafts outside the graph and offer a labeled repair form using the existing parent/task pickers; never hide a conflict by exporting only the shared baseline. Preview the actual new versions and parents before publishing. Disable shared mutations while disconnected and keep local file operations separate.
- Account headers reuse the workspace branch mark and keep “IQAN Archive” on one line, with a quiet account-center subtitle below it. Use a compact 68px header, a visible 44px return action, and responsive gutters; never place the brand's individual words in separate grid rows.
- Member management loads the current list on entry and updates reset/enable results immediately. Account deletion requires a focused inline confirmation naming the member and explaining session revocation, retained task references and unsynced drafts; never offer deletion for admin. Show reused-password errors beside the new-password field with an accessible description, preserve failed forms and valid sessions, and require login only after a successful password change.
- Member rows group display name, monospace username and textual enabled status. Keep enable/disable and outlined red Delete actions together, at least 44px tall, without stretching them across the row; stack identity above the action group on narrow screens. Reserve the filled destructive style for the final deletion confirmation.
- Background host checks never display a blocking progress overlay. After the current operation finishes, show connection ambiguity or an actual host change in a focused native dialog, including the no-replay and reconnect requirements. Provide a visible acknowledgement and Escape dismissal, restore available prior focus, and remain usable over account pages. An unchanged unique host stays silent.
- Keep shared/local root settings in a compact two-column control; place each file panel's scan-location selector beside its derived project path, and identify the selected source in its preview without repeating scanning rules.
- In the project rail, keep the project name and full part number on separate lines; render version-linked engineering files and comparison documents as aligned compact source rows with visible source labels.
- Align the top edges of the project rail and active workspace; rely on the outer grid gap for stacked spacing instead of an extra workspace top margin.
- Allow the entire project rail to collapse without unmounting forms, retaining a visible 44px expand control. In the collapsed state, center the wide workspace with symmetric gutters; on narrow screens place the expand control above it to preserve usable width. Resize only the history viewport with a 44px bottom-right handle, bounded by its column width; arrow keys adjust size and Home restores defaults. Keep toolbar and inspector geometry independent. Layout preferences are session-only.
- Provide native fullscreen for the graph with elevated floating control and inspector surfaces. Allow both to collapse without discarding form input. Reserve desktop space so focused graph rows remain unobscured; on narrow screens use a dismissible inspector overlay. Keep an exit control visible when tools collapse, honor native Escape, and restore normal geometry on exit. Fullscreen is view-only state, not a graph command.
- Use layered dark surfaces, thin cool borders, restrained shadows, and consistent 8/12/16/24px spacing.
- Render the version graph as a Git-style vertical history, not a fit-to-canvas DAG. Parent-child edges determine row order; branch-colored rails and compact branch-head labels sit beside readable version/description text, with the description directly below the version number. Keep branch labels visually secondary with a neutral surface and border, using branch color as a clearly visible 6px leading stripe. Give selected labels a brighter border, raised background, and stronger text weight; preserve distinct hover and keyboard-focus states. Show release state on the rail node using the node's current branch color and a contrasting outlined check; keep unreleased nodes hollow. Selection uses row background/border feedback and never fills the node. Put nodes with no parent or child edges in a distinct unassociated-version column. Keep row height stable so long histories scroll instead of shrinking.
- Show testing-in-progress versions with a distinct clock-in-shield icon next to the version, an accessible state name and text in details; preserve branch colors and do not rely on warning color alone. Collapsed task groups report the counts of released, testing and unreleased versions.
- Put a fixed engineering-file location status icon immediately before each version's comparison-document action: computer for local, cloud for shared, a combined mark for both, and a crossed file for neither. Match its 28px frame, border, and surface to the document action; keep the same slot width for regular and unassociated rows. A toolbar toggle hides/shows both file icons together and reclaims their width when hidden. Expose the full state as an accessible label. Show an unknown scan mark when either root is missing, unauthorized, or could not be scanned; never imply no files from an incomplete scan.
- Keep graph navigation predictable: native vertical scrolling, Shift+wheel horizontal scrolling, and cursor-anchored Ctrl+wheel/toolbar zoom. Zoom must not pan the first row out of reach. Remove node and canvas dragging; use explicit selection, menus, and the searchable parent-version picker for graph edits. Preserve local scrolling for large tables and graphs.
- Route cross-lane edges with a one-row-high curve beside the inner-lane endpoint and a vertical outer-lane segment for the remaining history. Preserve this fork/merge geometry in either sort direction instead of stretching curves across intervening rows.
- Branch scope uses a searchable checkbox dropdown with independent, unlimited multi-selection, Show All, and Clear All. Selected histories form a union without duplicate ancestors; isolated versions remain visible even with no branches selected. Search only narrows the choices, never clears hidden selections. Keep the dropdown open while toggling and support keyboard focus, Escape, and outside-click dismissal.
- Keep graph editing in the right-hand inspector, replacing its read-only details while an operation is open. On desktop, provide a draggable, keyboard-operable vertical separator to redistribute graph/inspector width, keeping at least 280px on each side and 360px as the default inspector width. Hide the separator in narrow-screen and fullscreen layouts; keep width preferences session-only. Include version, parent, merge, branch, and deletion forms. Constrain its height and scroll only the inspector; focus the first editable field without scrolling the page, then return focus to the graph on close. On narrow screens, use a dismissible right-hand overlay with internal scrolling and a visible close control, never a form below the graph.
- Allow only branch labels to drag onto version rows, highlight the target, and require a modal confirmation showing old/new heads before writing. Keep nodes and canvas non-draggable. The branch editor provides the equivalent explicit head selector for keyboard and single-pointer users.
- Add parents with one compact row: an editable combobox with an inset dropdown arrow and an explicit Add button. Filter the version-adjacent recommendations by version/description as the user types; require an actual option selection before enabling Add. Keep options locally scrollable with an empty state and Arrow/Enter/Escape keyboard support.
- Reuse this parent picker for each child in deletion reconnection previews, preserving automatic initial parents and showing removable selected items instead of a wall of candidate checkboxes. Keep each child's search independent and released children read-only.
- Prefer flat SVG icons with visible keyboard focus, accessible names, and a 44px minimum control target.
- Version information hints use the same dark raised surface, cool-blue accent, thin border and restrained shadow as graph panels. Show full version, release text and multiline description on hover/focus; use a viewport-bounded top-layer popover, keep it hoverable and scrollable, and support Escape dismissal instead of native white title tooltips.
- Render version descriptions as Markdown in a bordered, cool-blue-accented panel separated from graph metadata. Keep the edit/preview modes keyboard-accessible, preserve line breaks, and do not execute raw HTML or fetch Markdown images.
- Use one bordered writing surface for Markdown fields. Place the field label above it, with mode selection and height toggle on the right. Group flat formatting icons inside the top edge; give icons accessible names, visible focus, and 44px targets. Long content scrolls inside the editor without moving its toolbar.
- Keep the comment formatting toolbar on one line. Prioritize common actions, and move tools that do not fit into a trailing ellipsis popover with text labels and native keyboard dismissal.
- Beneath a saved task description, show a compact attribution line with a small circular avatar and “姓名 创建于 时间” / “姓名 更新于 时间”, separated by a thin divider. If the account is the same, use one avatar. Allow groups to wrap on narrow screens and use initials when a profile image is unavailable.
- Show Cancel and Save only for a changed existing task description, side by side immediately below the editor border and flush with its right edge. Use a borderless text Cancel and a compact blue Save while keeping 44px hit areas and visible focus; do not use a full-width footer panel. Keep the editor mounted while saving. Edit links in a compact panel with labeled text/address fields, inline validation, and explicit Cancel/Apply actions. Keep checklist controls keyboard-operable and wide tables locally scrollable.
- Pointer-triggered version hints appear once at the initial pointer position with a 16px bottom-right offset, flipping left/up at viewport edges and keeping an 8px viewport margin. They stay stationary while the pointer moves within the row. Keyboard focus retains row-anchored positioning.
- Use transparent icon controls instead of filled, bordered toolbar buttons. Graph commands, file selection/sort, and directory scan actions use a small caption below the icon; hover and keyboard focus disclose supplemental hints. Keep filter labels, menu text, form submissions, registration counts, and destructive confirmations explicit. Disabled tools remain visibly disabled and cannot execute.
- Preserve visible status text for loading, empty, success, disabled, and error states. Never rely on color alone.
- Backend settings use a 720px maximum dialog with a prominent selected-address panel, fixed HTTP 80 / 3-second timeout badges, a labelled add-device input and explicit Add action. Accept space/comma-separated batches with no item-count cap. Show devices as two-column cards on desktop and a single column on narrow screens; use monospace names, status icons and readable testing/reachable/unreachable labels. Update completed probes immediately but select a host only after all probes finish. Collapse per-device failure details and connection/Launcher help to avoid repeating long instructions. Keep Save secondary and Test primary, require saving changed names before testing, and offer an explicit Restore Defaults without replacing saved custom/empty lists. Clear selection on zero/multiple reachable hosts and focus an actionable error summary. Maintain 44px controls and narrow-screen internal scrolling; the desktop footer must not obscure focused content.

## Motion

- Use Vue's built-in `Transition`/`TransitionGroup` and CSS for short list, feedback, and surface transitions; do not add an animation package for these effects.
- Keep motion subtle and non-blocking. Do not animate graph geometry in a way that obscures relationships or interferes with pointer operations.
- Honor `prefers-reduced-motion` by removing non-essential movement and minimizing transition duration.

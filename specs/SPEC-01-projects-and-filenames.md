# SPEC-01 项目与工程文件名解析

- 规格状态：框架
- 实施状态：未开始
- 范围：核心
- 关联需求：REQ-001、REQ-002、REQ-009、REQ-010
- 真实前置依赖：SPEC-00 的项目、版本和文件元数据契约
- 未决阻塞：Q-005、Q-009、Q-014；Q-002/006 已由第八轮确认；启动协议实现另见 SPEC-04/05

## 1. 目标

让用户按软件零件号维护项目，并把支持的 IQAN 工程文件名转换为可校验的零件号、版本号及候选日期信息，作为版本图的候选来源。

## 2. 范围

- 包含：多项目登记；软件零件号；工程/Word 对比文档两类目录地址提示与授权选择；识别 `.idax`、`.idsx`、`.idvx`，按已确认语法解析和定位工程文件。
- 明确不做：将原工程/Word 二进制搬入 Dexie.js 或 JSON、改写源文件、自动解析 IQAN 内部内容、内容比较。自动建节点去重、Word 关联/预览待定；本地启动由独立协议启动器负责。
- 已确认样例：`14798046801 V1.0-3 20261022.idax` 中期望提取 `14798046801` 和 `V1.0-3`。日期 `20261022` 是待确认含义的候选字段，不使用系统修改时间替代。

## 3. 功能与交互规则

框架建议：

1. 用户可建立多个项目；项目显示其软件零件号，并可按项目进入版本图。
2. 用户选择或提供工程文件名时，解析器先识别扩展名，再提取候选零件号、版本号与日期。
3. 解析出的零件号与当前项目不一致时，不自动静默归档；须显示冲突并让用户选择项目或取消。
4. 解析失败时保留原始文件名并给出原因；在有元数据录入路径的前提下允许用户修正，不伪报解析成功。
5. Q-002 已确认：同项目版本号 trim 后区分大小写且唯一，不同日期的同版本文件是一个节点的多个快照，打开/对比前明确选文件；重复来源导入细则仍受 Q-005 约束。
6. `.idax`、`.idsx`、`.idvx` 大小写、重复扩展名及文件名中额外空白的处理尚待 Q-005 确认。

### 双目录与本地能力边界

- 每项目可分别输入工程目录与 Word 对比文档目录的地址提示，并通过显式“选择目录”操作授权绑定。提示可以是用户填写的 Windows 路径，但浏览器通常不会提供可用于任意 EXE 的真实绝对路径；不能据此推导访问权限。
- 目录选择只请求读取权限；用户取消时不替换已有绑定，权限拒绝/失效时保留配置、明确显示未授权并允许重新绑定。
- 选择目录不是导入全部二进制；仅按已定规则枚举候选文件和元数据，不上传、不修改源文件。是否递归和文件数量上限见 Q-009/Q-012；在未定前不开展无界扫描。
- 节点的文件引用建议由目录角色、相对路径、原文件名及候选元数据构成；移动/更名/多候选时提示缺失或冲突，不仅凭版本号自动打开（Q-014）。
- Word 目录仅配置和授权；`.doc/.docx` 范围、版本对比文档命名/关联、预览与打开均见 Q-009，不视为已提供在线 Word 功能。
- 单项目 JSON 恢复后两个目录均为“待绑定”。保留原路径提示和相对引用，不自动恢复授权，也不自动扫描本机。
- 不支持 `showDirectoryPicker` 的浏览器明确说明目录能力不可用；项目元数据/JSON 仍可浏览和管理，不伪装成持久目录访问。

### 节点右键打开工程（可选启动器）

- 本地打开及两节点对比见 [SPEC-04](./SPEC-04-iqandesign-integration.md)；本 SPEC 负责目录/文件定位，原 `SPEC-01-AC-08` 更新为请求/降级验收，不重复定义命令参数。
- “使用 IQANdesign 打开”通过 SPEC-04/05 自定义协议请求，提供右键/键盘/更多操作入口；未安装时显示安装/手动指引，不影响文件名及项目管理。
- 禁止将点击、`file://` 链接、下载文件或浏览器发出外部请求等描述为已经启动 IQANdesign。目录授权不能赋予启动进程权限。
- 已确定可选 Windows 协议启动器，无 HTTP 常驻服务。启动器独立设置项目 ID→工程根目录和程序路径，不继承浏览器授权；URI 无可信网页来源和可靠回传，需本机确认。细节见 [SPEC-05](./SPEC-05-windows-launcher.md)，本轮不安装或执行。

## 4. 必要接口与数据

| 边界 | 输入 | 候选输出 |
| --- | --- | --- |
| 项目校验 | 项目名称/标识（如要求）、软件零件号 | 可显示的项目记录或字段级校验错误 |
| 扩展名识别 | 文件名 | 支持的扩展名或明确的“不支持格式”结果 |
| 文件名解析 | 完整文件名 | `partNumber`、`version`、可选 `date`、`extension`、解析状态与失败原因 |
| 项目匹配 | 解析出的零件号、候选项目 | 唯一匹配/无匹配/多个匹配；不得静默猜测 |
| 目录绑定 | 用户手势、目录角色、路径提示 | 已绑定/未绑定/拒绝/失效/不支持等状态；授权句柄留本机 |
| 文件定位 | 项目、工程目录绑定、节点来源引用 | 唯一候选/缺失/多候选/未授权；不回退到任意同版本文件 |
| 启动请求 | 用户显式点击、项目 ID 与相对引用 | 协议请求或可捕获错误；安装/启动结果未知，本机负责最终文件校验 |

样例解析期望（不是正式语法）：

| 文件名 | 零件号 | 版本号 | 日期候选 | 后缀 |
| --- | --- | --- | --- | --- |
| `14798046801 V1.0-3 20261022.idax` | `14798046801` | `V1.0-3` | `20261022` | `.idax` |

项目名称和零件号必填，不同项目可有相同零件号。文件名完整字符/分隔符/日期语法及解析优先级仍待 Q-005；使用纯函数校验，不读取专有二进制内容。基础项目创建已在 SPEC-00 实现，不代表解析/目录 UI 已实施。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| 扩展名不支持 | 明确显示支持的扩展名；不读取/写入文件。 | 重新选文件或取消。 |
| 文件名字段缺失/格式不符 | 标记为未解析并保留原文件名。 | 用户修正命名或人工确认字段。 |
| 零件号与当前项目不匹配 | 展示冲突，不自动跨项目写入。 | 选择正确项目或取消。 |
| 日期像日期但无效 | 按最终规则拒绝或标注为原始文本；不得生成错误排序日期。 | 修正文件名或人工编辑。 |
| 重复版本号/重复导入 | 多日期快照属于同一节点，不静默覆盖。 | Q-002 已确认；重复来源处理待 Q-005。 |
| 路径已填但未授权/权限失效 | 显示配置存在但无法读取，不伪报已绑定。 | 用户手势重新选择目录。 |
| 文件被移动、同版本存在多个文件 | 显示无法定位/多候选，不自动选择错误工程。 | 用户确认重绑或选择候选。 |
| JSON 包含越界相对路径 | 拒绝绝对路径/`..` 等作为授权目录内的文件定位，不读目录外数据。 | 修正引用或重新选择文件。 |

## 9. 来源、未决事项与风险

- 来源：用户提供的目标及截图中的文件名；截图包括同一 `V1.0-3` 的多个日期文件。
- Q-001/Q-013 已解决选型；Q-002、Q-005、Q-006、Q-009、Q-014 仍限制正式解析、扫描与定位。本机映射/协议的未决细节不阻塞独立元数据功能。
- [MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)：已于 2026-10-29 核实需安全上下文、用户激活，且并非所有浏览器支持；实施前核实目标浏览器兼容。
- [MDN File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)：已核实文件访问基于用户许可与句柄；路径字符串不是授权。

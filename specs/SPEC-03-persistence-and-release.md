- 规格状态：可实施
- 实施状态：部分完成（schemaVersion 4 JSON 导出/恢复已实现；Pages 实站及本机平台验收未完成）
- 范围：核心基础能力与配置 JSON 恢复；不含工程/软件对比文档二进制备份
- 关联需求：REQ-001、REQ-003、REQ-005、REQ-007、REQ-008、REQ-009、REQ-011–REQ-016、REQ-018、REQ-019（绑定隔离）、REQ-020、REQ-036
- 真实前置依赖：SPEC-00、SPEC-01、SPEC-02 的项目元数据与图关系契约，供完整持久化往返使用；扫描关联不是 JSON 数据
- 未决阻塞：无。Q-012 的原 schemaVersion 3 决策由 SPEC-07 的 schemaVersion 4 明确升级；Q-007/010/011/018 已解决。JSON 导入/导出已实现；Pages 线上切换与本机平台验收另行记录。

## 1. 目标

确保用户创建的项目和版本图可按确认策略可靠保存、恢复，并为静态网站发布准备验证清单。此阶段不假定浏览器本地存储能够跨设备同步或永久保管工程文件。

## 2. 范围

- 包含：Dexie.js 配置持久化、保存/错误反馈、显式 schema 迁移、单项目 JSON 配置导出恢复（文件位于统一归档根目录）、项目子目录重新扫描、静态托管验收。
- 已确认：工程和软件对比文档留在统一归档根目录的项目子目录；JSON 只保存配置/版本信息，不是工程文件备份，也不含归档根目录句柄。
- 2026-11-06 用户确认 JSON 直接在授权根目录读写；2026-11-10 用户明确 JSON 导入/导出默认使用共享根目录。导出写入共享根目录顶层，导入列出共享根目录顶层 JSON；不自动回退本地根目录。共享目录选择及 JSON 文件访问沿用其读写授权。
- 已确认：JSON 最大 20 MiB、最多 100,000 个图实体、任务选项和评论；同项目 ID 或内部 ID 冲突时，经预览确认后作为副本导入并重映射全部内部 ID；不同项目 ID 的零件号重复合法。当前读写 schemaVersion 4；schemaVersion 3 显式迁移至 v4，schemaVersion 1/2 及未知版本拒绝；看板字段归 SPEC-07。
- 单人本机多标签页已确认，任务展开状态不持久化；其他视图偏好不进入本次 JSON。
- 不包含：默认云同步、账号、多用户权限或服务器备份；这些需用户明确提出并确认架构变化。

## 3. 功能与交互规则


- 用户编辑后的数据必须明确反馈保存中/成功/失败状态；保存失败不得提示成功。
- 使用前说明配置保存在当前站点/浏览器中；清除浏览器数据可能丢失配置，需主动导出 JSON。原工程/软件对比文档不由本工具保管，JSON 不包含它们。
- 每个项目提供导出 JSON 与导入恢复入口。默认在已授权共享根目录顶层创建不覆盖旧文件的 `.json` 备份，并从该共享根目录顶层选择 JSON 导入；共享根目录未设置/无读写权限时明确提示，不回退到本地根目录、浏览器下载或任意文件选择器。导出是完整项目配置的一致性快照，不受任务折叠、当前选中节点或过滤视图影响。
- 导入前检查大小、编码/JSON 格式、schema 版本、类型/字段范围、实体数及所有引用，预览项目与数量、冲突及“文件未包含/需重绑”提示；规则不明时不擅自覆盖。
- 项目 ID 或任一内部实体 ID 冲突时，预览明确提示；用户确认后作为新副本导入并一致重映射项目、节点、父边、分支、任务及全部引用。零件号不具唯一性，不同项目零件号相同不构成冲突。
- 导入只写出 schemaVersion 4，JSON 文件不超过 20 MiB，节点/边/分支/任务/选项/评论合计不超过 100,000 条；超限在写库前拒绝。schemaVersion 3 按 SPEC-07 显式迁移至 v4，schemaVersion 1/2 和未知版本拒绝。
- 导入数据库操作为单个 Dexie.js 原子事务；校验或提交失败不部分写入。文件读取、JSON 校验、目录选择和用户确认在事务外完成。
- 导入 JSON 不提供任何目录授权。若当前浏览器已有全局根目录，则按导入项目名称推导工程/文档子目录，分别检查并由用户扫描；若无根目录则先授权根目录。不得把 JSON 中的提示显示为实际绑定，不自动运行导入内容。缺少子目录时明确提示，不自动创建。
- 若导入前已有当前项目，导入后保留当前页面/项目，避免卸载未保存的编辑草稿；无当前项目时打开新导入项目的文件页。
- 确定发布至 GitHub Pages（HTTPS）；同时验证根站与仓库项目站的资源 base、刷新/深链接及适用的 worker/WASM。建议 hash 路由；若选 history 路由，必须给出并验证 Pages 刷新方案，不能依赖开发服务器兜底。
- 只发布应用构建产物；排除用户项目 JSON、工程/软件对比文档原文件、参考手册和本机启动器配置，不把工作区整个上传到 Pages。安装包的发布渠道按 Q-016 单独确定，不夹带 IQANdesign 软件。
- Pages 使用 `.github/workflows/deploy-pages.yml`：`main` 推送或手动触发后，Node 22.22.0 / `npm ci` → `npm test` → `npm run build` → 上传且只部署 `dist`。GitHub Settings → Pages → Build and deployment → Source 必须选择 **GitHub Actions**，不能用 Deploy from a branch 发布源码根目录。保留 Vite `base: './'`，当前无客户端路由，仓库子路径首页和刷新应加载构建后的相对资源。
- IndexedDB 按 origin 而非仓库路径隔离。同一 `<owner>.github.io` 下多个仓库项目可能同源，应使用本产品独立数据库命名避免误读；命名不是安全隔离，不在不可信同源应用间承诺数据隔离。
- 更换域名、浏览器/配置文件前提示导出 JSON，不能保证自动迁移或权限恢复。不保证离线可用，离线需另立需求并断网验证。
- 目标浏览器需验证 Dexie/IndexedDB、目录选择和外部协议能力；目录 API 支持有限，Windows 支持协议也不代表浏览器允许激活。非 Windows/不支持目录或协议时提供明确说明，保留元数据/图/JSON 能力。

## 4. 必要接口与数据

- 存储接口使用异步读写并暴露可区分错误（不可用、配额不足、版本迁移失败、导入格式无效）。
- Dexie.js 已在 SPEC-00 安装；当前数据库 v7 保存全局 `archiveRoots` 根目录句柄及项目任务看板字段，保留旧 `directoryBindings` 表但当前授权流程不再读取/写入。v1 版本规范化冲突检测、`externalTaskId` 规则不变；旧 JSON schema 不兼容。
- 数据 schema 迁移必须显式版本化，并保留恢复/备份策略。
- 当前独立表：projects、nodes、edges、branches、tasks、旧 `directoryBindings`（兼容）、`archiveRoots`（全局根句柄）；数据库 v7 不持久化扫描关联。图数据按稳定 project ID 隔离；根目录是本机全局设置，不属于图或 JSON 配置。
- 当前 JSON schemaVersion 4 包含项目元数据、版本节点/说明、父边、分支、任务看板选项/字段/评论及放行状态；不包含统一根目录句柄、项目子目录路径、文档匹配结果或扫描缓存。schemaVersion 3 显式迁移至 v4：保留图/任务身份、初始化项目 Status/Type 默认选项，旧任务看板字段置空并按名称/稳定 ID 生成泳道顺序；schemaVersion 1/2 拒绝。恢复后沿用本机根目录（如已授权），按项目名重新扫描子目录；未授权则重新选择根目录。布局偏好不加入 JSON。
- 任务按 [SPEC-00](./SPEC-00-foundation.md) 保存可空字符串 `externalTaskId`，纳入 Dexie.js 与项目 JSON；不保存外部系统链接、账号、令牌或同步状态。外部 Task ID 是系统无关的用户编号，不是内部主键，也不证明远端记录存在。
- 同项目非空外部 Task ID 唯一性由事务与 `[projectId+externalTaskId]` 索引保证；跨项目同编号及多个 null 合法。编号仅允许 1–16 位 ASCII 数字，trim 后保留为字符串（含前导零），不把外部 ID 当内部主键；完整导入还需同样校验。
- 当前任务外部编号字段为 `externalTaskId`，唯一索引为 `[projectId+externalTaskId]`；看板字段使用任务选项稳定 ID，项目内每个任务最多一个 Status、Type、priority 和 assignee，并保存可空开始/截止日期及评论。schemaVersion 4 保存完整任务看板配置；字段契约见 SPEC-07 REQ-036。
- JSON 导入验证 `externalTaskId` 类型、1–16 位数字规则和项目内非空唯一性；非数字、超长或同项目重复编号整体拒绝并指出任务/字段，不静默清空、转换、覆盖或合并。旧配置含非法值时须先显式修正。恢复为副本时保留合法外部 Task ID，仅重映射内部 ID 与内部引用。
- 导出/恢复预览说明包含用户录入的外部 Task ID，可能暴露内部任务信息；仍仅在本地处理，不读取或同步外部系统。
- JSON 不含二进制、FileSystemHandle、目录提示、本地文件引用、权限/令牌、EXE 命令、可执行脚本或可执行 HTML。不通过当前目录选择 API 获取或猜测完整路径。schemaVersion 1/2 与未知版本拒绝；v3 仅通过上述显式迁移映射到 v4。
- [SPEC-04](./SPEC-04-iqandesign-integration.md) 的临时双选、有序预览、协议请求不加入项目 JSON；不新增对比历史，也不将软件对比文档目录当报告输出目录。本机启动器映射与 EXE 设置不属于浏览器数据，不能通过导入 JSON 创建/修改。
- 新设备恢复需重新选择浏览器全局根目录并确保项目子目录按项目名存在；Launcher 仍使用独立本机配置并逐次确认。副本项目按副本名称查找对应子目录，不自动继承其他项目的子目录或从 JSON 恢复授权。
- 验证同项目闭合引用（节点/父边/分支头/任务/看板选项/assignee）、重复 ID、合法日期/状态、无循环、放行祖先闭包及评论时间；schemaVersion 1–3 不接受；兼容迁移须显式定义并预览。
- 作为副本导入时一致重映射项目、节点、父边、分支、任务及全部关联；不得替换/合并已有项目或复用目录权限。
- Q-012 已确认：20 MiB 文件上限、100,000 个实体上限、ID 冲突确认后导入为副本；同零件号不同项目允许并存。原 schemaVersion 3 only 限制已被 SPEC-07 看板 schemaVersion 4 决策取代，当前 v4 only。只做配置备份，不引入二进制打包库。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| 浏览器拒绝/不支持持久化 | 明确说明数据未可靠保存，提供符合确认策略的替代路径。 | 用户重试或导出可恢复数据。 |
| 配额耗尽 | 告知保存失败和可能影响，不删除旧文件/记录来伪装成功。 | 用户清理或导出后再试。 |
| 迁移失败 | 不继续写入可能损坏的数据，保留错误详情与恢复入口。 | 使用备份恢复或人工处理。 |
| 备份文件无效/版本不兼容 | 校验后拒绝导入，不部分覆盖当前数据。 | 选择有效备份或保留原项目。 |
| 静态子路径/刷新 | 资源与路由返回正确页面，不依赖开发服务器兜底。 | 修正构建 base/path 后再验收。 |

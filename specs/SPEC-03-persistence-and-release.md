# SPEC-03 本地持久化与发布准备

- 规格状态：框架
- 实施状态：未开始
- 范围：核心基础能力与配置 JSON 恢复；不含工程/软件对比文档二进制备份
- 关联需求：REQ-001、REQ-003、REQ-005、REQ-007、REQ-008、REQ-009、REQ-011–REQ-016、REQ-018、REQ-019（绑定隔离）、REQ-020
- 真实前置依赖：SPEC-00、SPEC-01、SPEC-02 的数据、文件引用与图关系契约，供完整持久化往返使用
- 未决阻塞：Q-012；Q-007/010/011/018 已由第八轮确认。基础事务已在 SPEC-00 实现，完整导入恢复/部署仍未实施。

## 1. 目标

确保用户创建的项目和版本图可按确认策略可靠保存、恢复，并为静态网站发布准备验证清单。此阶段不假定浏览器本地存储能够跨设备同步或永久保管工程文件。

## 2. 范围

- 包含：Dexie.js 配置持久化、保存/错误反馈、显式 schema 迁移、单项目 JSON 配置导出恢复、目录重新绑定、静态托管验收。
- 已确认：工程和软件对比文档留原目录；JSON 只保存配置/版本信息，不是工程文件备份。
- 待定：JSON 上限、项目冲突策略、兼容版本及其余视图偏好；单人本机多标签页已确认，任务展开状态不持久化。
- 不包含：默认云同步、账号、多用户权限或服务器备份；这些需用户明确提出并确认架构变化。

## 3. 功能与交互规则

- 用户编辑后的数据必须明确反馈保存中/成功/失败状态；保存失败不得提示成功。
- 使用前说明配置保存在当前站点/浏览器中；清除浏览器数据可能丢失配置，需主动导出 JSON。原工程/软件对比文档不由本工具保管，JSON 不包含它们。
- 每个项目提供导出 JSON 与导入恢复入口。导出是完整项目配置的一致性快照，不受任务折叠、当前选中节点或过滤视图影响。
- 导入前检查大小、编码/JSON 格式、schema 版本、类型/字段范围、实体数及所有引用，预览项目与数量、冲突及“文件未包含/需重绑”提示；规则不明时不擅自覆盖。
- 项目 ID/零件号冲突的副本/替换/合并策略见 Q-012，确认前遇冲突停止导入。不得只因为零件号相同就覆盖已有项目。
- 导入数据库操作为单个 Dexie.js 原子事务；校验或提交失败不部分写入。文件读取、JSON 校验、目录选择和用户确认在事务外完成。
- 导入成功后工程与软件对比文档目录均标记“待重新绑定”，不得把旧目录提示显示为实际绑定；用户显式授权后自动保存本机句柄、显示实际目录名并恢复定位，不自动运行导入 JSON 中的任何内容。
- 确定发布至 GitHub Pages（HTTPS）；同时验证根站与仓库项目站的资源 base、刷新/深链接及适用的 worker/WASM。建议 hash 路由；若选 history 路由，必须给出并验证 Pages 刷新方案，不能依赖开发服务器兜底。
- 只发布应用构建产物；排除用户项目 JSON、工程/软件对比文档原文件、参考手册和本机启动器配置，不把工作区整个上传到 Pages。安装包的发布渠道按 Q-016 单独确定，不夹带 IQANdesign 软件。
- IndexedDB 按 origin 而非仓库路径隔离。同一 `<owner>.github.io` 下多个仓库项目可能同源，应使用本产品独立数据库命名避免误读；命名不是安全隔离，不在不可信同源应用间承诺数据隔离。
- 更换域名、浏览器/配置文件前提示导出 JSON，不能保证自动迁移或权限恢复。不保证离线可用，离线需另立需求并断网验证。
- 目标浏览器需验证 Dexie/IndexedDB、目录选择和外部协议能力；目录 API 支持有限，Windows 支持协议也不代表浏览器允许激活。非 Windows/不支持目录或协议时提供明确说明，保留元数据/图/JSON 能力。

## 4. 必要接口与数据

- 存储接口使用异步读写并暴露可区分错误（不可用、配额不足、版本迁移失败、导入格式无效）。
- Dexie.js 已在 SPEC-00 安装，SPEC-01 升为数据库 v2，新增独立本机目录句柄表；v1 升级先检查版本规范化碰撞，失败回滚，不猜测重写旧图。许可 Apache-2.0，具体版本见锁文件；本规格仍负责完整 JSON 恢复和部署。
- 数据 schema 迁移必须显式版本化，并保留恢复/备份策略。
- 建议独立表：projects、versionNodes、edges、branches、tasks、fileReferences、localBindings。最终索引与实体字段按 SPEC-00 定案；所有项目数据按稳定 project ID 隔离，导入/放行为跨表事务。
- JSON 包含 `schemaVersion`、项目元数据、全部版本节点/改动说明、真实父边、分支头/信息/颜色、任务与节点关联、放行状态、兼容旧两类目录提示字段和文件相对引用。旧提示不再编辑或作为当前绑定展示；实际绑定目录名来自本机句柄，不另存完整路径。导出时间/生成器版本可作为建议字段；布局与浏览偏好只有确认保存后才加入。
- 任务按 [SPEC-00](./SPEC-00-foundation.md) 保存可空字符串 `loopId`，纳入 Dexie.js 与项目 JSON；不保存卡片链接、远端账号、令牌或同步状态。它只是用户提供的关联编号，不携带 Loop 权限。
- 同项目非空 Loop ID 唯一性由事务与 `[projectId+loopId]` 索引保证；跨项目同编号及多个 null 合法。Q-018 已确认 trim/区分大小写/最多 16 码点，不把外部 ID 当主键；完整导入还需同样校验。
- SPEC-00 首次 schema v1 已包含 `loopId`，无旧发布版本；后续变更须显式升级迁移，仅对明确支持的旧备份定义缺字段转 null，不改内部引用、不猜编号，未知版本拒绝。
- JSON 导入验证 `loopId` 类型、Q-018 最终字段规则和项目内非空唯一性；同项目重复编号整体拒绝并指出任务/字段，不静默清空、覆盖或合并。恢复为副本时若 Q-012 最终采用该策略，保留 Loop ID，内部身份按原重映射规则处理，外部编号不是重映射目标。
- 导出/恢复预览说明包含用户录入的 Loop 编号，可能暴露内部任务信息；仍仅在本地处理，不读取卡片或上传/同步到 Loop。
- JSON 不含二进制、FileSystemHandle、权限/令牌、EXE 命令、可执行脚本或 HTML。旧目录提示可能含用户路径，说明导出可能暴露这些信息，不上传第三方；不通过当前目录选择 API 获取或猜测完整路径。
- [SPEC-04](./SPEC-04-iqandesign-integration.md) 的临时双选、有序预览、协议请求不加入项目 JSON；不新增对比历史，也不将软件对比文档目录当报告输出目录。本机启动器映射与 EXE 设置不属于浏览器数据，不能通过导入 JSON 创建/修改。
- 新设备恢复必须分别重绑浏览器目录和启动器项目目录；同设备旧 ID 绑定也不能被导入覆盖或免确认。副本 ID 改变后不自动继承旧绑定，防止开错项目；本机每次确认最终路径。
- 验证同项目闭合引用（节点/父边/分支头/任务/文件引用）、重复 ID、合法颜色/状态、无循环、放行祖先闭包和授权目录内的安全相对引用。未知 schema/缺少必需状态不能静默赋值；兼容迁移须显式定义并预览。
- 恢复为副本时若最终选择该策略，必须一致重映射项目及关联 ID，而不是只换 project ID；替换/合并和目录权限复用均不能自动决定。
- 数据大小上限、冲突策略与旧版兼容范围见 Q-012；具体数值在有数据规模依据后确定，不写任意阈值。只做配置备份，不引入二进制打包库。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| 浏览器拒绝/不支持持久化 | 明确说明数据未可靠保存，提供符合确认策略的替代路径。 | 用户重试或导出可恢复数据。 |
| 配额耗尽 | 告知保存失败和可能影响，不删除旧文件/记录来伪装成功。 | 用户清理或导出后再试。 |
| 迁移失败 | 不继续写入可能损坏的数据，保留错误详情与恢复入口。 | 使用备份恢复或人工处理。 |
| 备份文件无效/版本不兼容 | 校验后拒绝导入，不部分覆盖当前数据。 | 选择有效备份或保留原项目。 |
| 静态子路径/刷新 | 资源与路由返回正确页面，不依赖开发服务器兜底。 | 修正构建 base/path 后再验收。 |

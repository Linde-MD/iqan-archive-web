# SPEC-07 项目任务看板

- 规格状态：可实施
- 实施状态：未开始
- 范围：核心
- 关联需求：REQ-033
- 真实前置依赖：SPEC-00 任务稳定 ID、项目事务及版本关联契约；SPEC-02 图内任务投影；SPEC-03 看板数据 schema v5 / JSON schemaVersion 4 契约（不要求 JSON 导入 UI 先完成）
- 未决阻塞：无

## 1. 目标

在每个项目中提供独立任务管理页面，按 Status 看板管理任务，并能在任务卡片与关联软件版本图节点之间双向定位。任务与选项仅保存在当前浏览器，不连接或同步外部系统。

## 2. 范围

- 包含：项目入口、Status 泳道看板、任务字段编辑、Status/Type 选项维护、拖拽与键盘替代操作、版本关联列表及图/看板导航。
- 不包含：Loop 登录、卡片链接、外部读取/同步、跨项目任务、多人协作、版本图关系编辑或 IQAN 文件内容操作。
- Task ID 指现有外部编号字段 `externalTaskId`，显示名称为“Task ID”；内部稳定 `Task.id` 和节点引用 `taskId` 不改变，校验继续沿用同项目唯一、1–16 位 ASCII 数字规则。
- Type 初始名称按用户截图中可辨内容记录为临时值，包含 `Project Devel...`、`Series Mainte...`、`Field/After-...`、`CO Support`、`Bug/Issue`、`Technical Imp...`、`Internal`。省略号表示截图标签被截断，不推断或补造完整名称；用户可在选项管理中改名。
- Status 初始选项按截图可辨顺序为 `Backlog`、`Pending`、`In Progress`、`release pending`、`Done`。新增选项追加到末尾。
- 设计沿用适用于工程工作台的深色控制台 token 与现有响应式组件规范，不采用 UI/UX Pro Max 通用营销页布局。UI/UX Pro Max `dark productivity dashboard kanban --domain style` 命中 `dark-mode-oled` 与 `data-dense-dashboard`；采纳高对比深色、可见焦点、减少动态效果及紧凑但可读的看板布局，不照搬纯黑霓虹或通用分析图表。UX 域“拖动操作需提供单指针替代及完整键盘操作”的指南适用；看板不允许仅靠拖拽操作。

## 3. 功能与交互规则

### 项目入口与看板

- 每个项目入口并列显示“管理文件”“版本分支图”“任务管理”三个图标按钮，均有可访问名称、可见焦点及当前选中状态；选择任务管理进入该项目独立看板页。
- 看板默认按 Status 分列泳道，列顺序采用选项顺序；无 Status 的任务显示在单独的“未分组”泳道。Type 作为任务属性，不作为默认分列字段。
- 每张卡片可见 Task ID（有值时）、任务名、Status 和 Type；长说明在详情中查看。卡片单击打开右侧任务详情/编辑面板，含 Task ID、任务名、Status、Type、Description、删除操作及全部关联软件版本。
- 任务名必填；Description 与 Task ID 可空。新建任务默认 Status 为 `Backlog`，Type 可不选。Status/Type 每项至多选择一个选项；未设置 Type 显示“未设置”。
- 任务创建、编辑、删除及选项维护遵循项目 revision 并发保护。删除任务沿用现有语义：确认后删除任务记录，只解除版本节点的 `taskId`，不改版本、父边、分支和放行状态。

### 选项维护

- Status 与 Type 选项在当前项目内分别维护，支持新增、重命名、删除；新增项按添加顺序显示，重命名保留选项稳定 ID 与现有任务引用。
- 删除选项若仍被任务使用，先明确显示受影响任务数量并要求确认。确认后删除选项并将这些任务的对应字段清空；不自动迁移到其他选项。Status 清空后任务进入“未分组”泳道；Type 清空后显示“未设置”。
- 选项名称去除首尾空白且不能为空；同类选项名称不可重复。失败保留输入、明确指出原因，不能部分修改。

### 拖动与可访问替代

- 卡片拖到另一 Status 泳道会更新其 Status；在同一泳道内拖动只改变该泳道顺序。提交原子持久化，刷新后状态/顺序不变；跨项目、失效选项或 revision 冲突时整体拒绝并显示错误。
- 使用官方 `@dnd-kit/vue` Vue 适配包，不引入 React。适配包要求 Vue 3.5+，仓库 `package.json` 声明的 Vue `^3.5.44` 满足版本范围；实施时仍须用 npm 锁定实际版本并按 package metadata 核实许可证与依赖。该包要求拖放 hooks 位于 provider 的后代组件中。
- 拖拽必须有键盘和单指针非拖拽等效操作：提供“移至”状态菜单/按钮及卡片上移、下移操作；拖拽不是唯一输入方式。拖动/菜单/按钮均暴露明确名称、焦点和状态，目标尺寸至少 44 × 44px。
- 状态修改和顺序保存只改任务看板数据，不进入版本图撤销栈，不修改任务与版本的关联、节点父边、分支或放行状态。

### 版本图双向跳转

- 在图的任务聚合模式中，Ctrl/Cmd+左键单击任务节点跳到同项目看板并选中对应内部 `Task.id` 卡片；任务节点普通点击仍执行展开/收起。键盘操作菜单提供等效入口。
- 看板详情列出该任务关联的所有软件版本；没有关联版本时显示明确空状态。点击一个版本跳到同项目版本图，切至全部版本模式以确保目标可见，滚动定位并突出对应版本节点。
- 跳转使用内部 ID/版本节点 ID，不依据可变 Task ID 或版本文本重新查找；导航不更改业务数据。切换项目时丢弃上一项目的焦点目标，目标不存在时明确提示并保留当前页面。

### 页面状态与响应式

- 提供项目无任务、无选项、加载中、保存中、保存失败和空泳道状态；错误不得伪装成保存成功。
- 桌面以可独立横向滚动的泳道区域及右侧详情面板呈现；窄屏允许泳道横向滚动，详情面板可关闭，不造成页面整体横向溢出。
- 支持键盘完整操作、可见焦点与 Escape 关闭详情；遵守减少动态效果偏好。正文对比度至少 4.5:1，状态不只靠颜色表达。

## 4. 必要接口与数据

- `Task` 保持稳定 `id`、`projectId`、`name`、`description` 和可空 `externalTaskId`；新增可空 `statusOptionId`、`typeOptionId` 和泳道内排序值 `sortOrder`。
- 每个项目保存有序 Status/Type 选项列表，每个选项有稳定 ID 与显示名称。Task 使用选项 ID 引用，不能把可编辑名称作为持久引用。
- 新建任务默认 Status 引用 `Backlog` 选项，Type 为 null。现有任务迁移后 Status/Type 均为 null，避免推断历史状态；任务显示于“未分组”，Type 显示“未设置”。
- Dexie v5 迁移已有项目的默认选项及任务空字段；现有任务按名称、再按稳定内部 ID 排序后分配确定性初始顺序。同一事务失败应回滚。项目修订号覆盖选项、任务字段和顺序变更。
- 配置 JSON schemaVersion 4 覆盖项目选项、Task ID、Status/Type 引用及卡片顺序；不加入文件信息、目录句柄、外部系统链接或同步数据。导入校验所有引用均属于同一项目。
- 页面导航状态（当前选中卡片、展开面板、临时高亮）不持久化。Task ID 仍作为字符串保留前导零。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| Task ID 格式非法或同项目重复 | 拒绝保存并提示 1–16 位数字/冲突任务；保留输入 | 用户修正后重试 |
| 删除仍被使用的选项 | 确认前列出影响数量；取消不变，确认后清空对应字段 | Status 显示于“未分组”，Type 显示“未设置” |
| revision 冲突或 IndexedDB 写入失败 | 不部分更新，显示可操作错误；不显示成功状态 | 重新读取项目后重试 |
| 拖动到无效泳道/目标已删除 | 不改变任务状态与顺序，提示重新加载 | 重新读取当前项目 |
| 跨页导航目标已删除/不存在 | 留在当前页并明确提示目标不可用 | 用户重新选择有效任务/版本 |

## 9. 来源、未决事项与风险

- 来源：用户提出独立任务管理页面、dnd-kit 看板、可维护 Status/Type、聚合节点跳转及版本详情反向跳转；用户确认使用 Vue 方案、Type 先按截图可辨标签设置初始值，并指定删除在用选项时确认后清空任务字段。
- dnd-kit 官方 [Vue Quickstart](https://dndkit.com/vue/quickstart/) 与仓库声明的 Vue `^3.5.44` 匹配；`@dnd-kit/vue` 0.5.3 的 npm 元数据要求 Vue `^3.5.0`、MIT 许可，包未安装，完整依赖和包体积须在实施时复核。Vue 检索未命中栈指南，不据空结果提出额外建议。
- UI/UX Pro Max 的看板设计系统检索返回不适用的营销页结构；style 域结果支持已确认的深色工程工作台方向，但其纯黑霓虹/图表建议不适用。拖拽移动需提供单指针及键盘替代操作。
- 截图中被截断的 Type 名称不具备可靠完整文本；初始值保留可辨的截断形式，用户可在应用内修改，不据此猜测完整名称。

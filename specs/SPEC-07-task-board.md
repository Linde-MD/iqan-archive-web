# SPEC-07 项目任务看板

- 规格状态：可实施
- 实施状态：核心实现完成；自动化和主浏览器流程通过，最终窄屏/人工可访问性验收记录待补
- 范围：核心
- 关联需求：REQ-033、REQ-036
- 真实前置依赖：SPEC-00 任务稳定 ID、项目事务及版本关联契约；SPEC-02 图内任务投影；SPEC-03 看板数据 schema v8 / JSON schemaVersion 5 契约（不要求 JSON 导入 UI 先完成）
- 未决阻塞：无。Q-022–Q-025 已于 2026-11-10 确认。

## 1. 目标

在每个项目中提供独立任务管理页面，按 Status 看板管理任务，并能在任务卡片与关联软件版本图节点之间双向定位。任务支持 assignee、开始/截止日期、可配置 priority 及可修改 comment。任务与选项仅保存在当前浏览器，不连接或同步外部系统。

## 2. 范围

- 包含：项目入口、Status 泳道看板、任务字段编辑、Status/Type/priority 选项维护、任务评论新增/修改、拖拽与键盘替代操作、版本关联列表及图/看板导航。
- 不包含：Loop 登录、卡片链接、外部读取/同步、跨项目任务、多人协作、版本图关系编辑或 IQAN 文件内容操作。
- Task ID 指现有外部编号字段 `externalTaskId`，显示名称为“Task ID”；内部稳定 `Task.id` 和节点引用 `taskId` 不改变，校验继续沿用同项目唯一、1–16 位 ASCII 数字规则。
- Type 初始名称按用户截图中可辨内容记录为临时值，包含 `Project Devel...`、`Series Mainte...`、`Field/After-...`、`CO Support`、`Bug/Issue`、`Technical Imp...`、`Internal`。省略号表示截图标签被截断，不推断或补造完整名称；用户可在选项管理中改名。
- Status 初始选项按截图可辨顺序为 `Backlog`、`Pending`、`In Progress`、`release pending`、`Done`。新增选项追加到末尾。
- REQ-036 已确认：assignee 使用项目内选项；日期为可空 `YYYY-MM-DD`，截止不得早于开始；priority 默认包含 `最高`、`较高`、`普通`、`最低`、`较低` 五档，任务默认仍为 null；每项可新增/删除/改名，并设置 1–3 个感叹号及六位颜色。评论为可新增/修改/删除的 Markdown 文本，保存创建/修改时间，不记录作者/修订历史。
- 设计沿用适用于工程工作台的深色控制台 token 与现有响应式组件规范，不采用 UI/UX Pro Max 通用营销页布局。UI/UX Pro Max `dark productivity dashboard kanban --domain style` 命中 `dark-mode-oled` 与 `data-dense-dashboard`；采纳高对比深色、可见焦点、减少动态效果及紧凑但可读的看板布局，不照搬纯黑霓虹或通用分析图表。UX 域“拖动操作需提供单指针替代及完整键盘操作”的指南适用；看板不允许仅靠拖拽操作。

## 3. 功能与交互规则

### 项目入口与看板

- 每个项目入口并列显示“管理文件”“版本分支图”“任务管理”三个图标按钮，均有可访问名称、可见焦点及当前选中状态；选择任务管理进入该项目独立看板页。
- 看板默认按 Status 分列泳道，列顺序采用选项顺序；无 Status 的任务显示在单独的“未分组”泳道。Type 作为任务属性，不作为默认分列字段。
- 每张卡片可见 Task ID（有值时）、任务名、Status 和 Type；长说明在详情中查看。卡片不显示独立拖动按钮，卡片非按钮区域通过指针移动启动拖动；点击卡片打开独立任务详情页，详情页含 Task ID、任务名、Status、Type、Description、删除操作、全部关联软件版本及评论，并提供返回看板入口。上移/下移按钮继续提供拖拽以外的排序操作。
- 任务名必填；Description 与 Task ID 可空。新建任务默认 Status 为 `Backlog`，Type 可不选。Status/Type 每项至多选择一个选项；未设置 Type 显示“未设置”。
- 任务创建、编辑、删除及选项维护遵循项目 revision 并发保护。删除任务沿用现有语义：确认后删除任务记录，只解除版本节点的 `taskId`，不改版本、父边、分支和放行状态。

### 新增任务字段与评论（REQ-036）

- 任务编辑面板应支持分配/清除 assignee、设置开始日期和截止日期、设置 priority，并查看该任务的评论列表。
- 评论支持新增、修改和删除；使用 Markdown 文本与安全渲染，保存 ISO UTC 创建/修改时间，不记录作者或修订历史，不加载图片。
- 看板卡片应以适合密集泳道的摘要呈现已设置的 assignee、priority 与日期；具体显示字段和日期格式须与最终数据规则一致，并在桌面/窄屏验收中避免卡片溢出。
- 开始日期、截止日期均可空；日期是否为本地日历日期或时间戳、以及截止早于开始时的处理由 Q-023 确认。priority 选项可由用户配置；初始选项、默认值、顺序及删除被引用选项的行为由 Q-024 确认。
- assignee 使用本地数据；在静态单用户产品边界内不增加登录或远端用户目录。具体采用自由文本还是项目内人员目录由 Q-022 确认。
- 日期控件使用本地日期输入，不转换 UTC 日期；非法日历日期和截止早于开始均拒绝，保留草稿并明确提示。
- 评论列表按创建时间从旧到新排列；每条评论提供查看、编辑和删除，删除前确认；渲染使用安全 Markdown，不执行原始 HTML、不加载图片。创建/修改时间以 ISO UTC 保存，不显示作者，不保留编辑历史。评论单条长度不另设上限，完整 JSON 仍受 SPEC-03 20 MiB 限额约束。

### 选项维护

- Status 与 Type 选项在当前项目内分别维护，支持新增、重命名、删除；新增项按添加顺序显示，重命名保留选项稳定 ID 与现有任务引用。
- 删除选项若仍被任务使用，先明确显示受影响任务数量并要求确认。确认后删除选项并将这些任务的对应字段清空；不自动迁移到其他选项。Status 清空后任务进入“未分组”泳道；Type 清空后显示“未设置”。
- 选项名称去除首尾空白且不能为空；同类选项名称不可重复。失败保留输入、明确指出原因，不能部分修改。
- priority 默认选项按 `最高`（!!!、`#f05252`）、`较高`（!!、`#f27ba5`）、`普通`（!!、`#eabf35`）、`较低`（!、`#35b8ed`）、`最低`（!、`#20bfa9`）初始化；任务默认 priority 为 null。用户可新增、重命名、删除选项，并编辑 1–3 个感叹号和颜色；删除被使用的 priority 选项前确认，确认后清空引用。卡片左边线显示优先级颜色，感叹号越多边线越粗；优先级名称保留可访问文本。

### 拖动与可访问替代

- 卡片拖到另一 Status 泳道的空白处或其他卡片上，均按指针释放所在泳道更新其 Status；在同一泳道内拖动只改变该泳道顺序。提交原子持久化，刷新后状态/顺序不变；跨项目、失效选项或 revision 冲突时整体拒绝并显示错误。
- 使用官方 `@dnd-kit/vue` Vue 适配包，不引入 React。适配包要求 Vue 3.5+，仓库 `package.json` 声明的 Vue `^3.5.44` 满足版本范围；实施时仍须用 npm 锁定实际版本并按 package metadata 核实许可证与依赖。该包要求拖放 hooks 位于 provider 的后代组件中。
- 拖拽必须有键盘和单指针非拖拽等效操作：提供“移至”状态菜单/按钮及卡片上移、下移操作；拖拽不是唯一输入方式。拖动/菜单/按钮均暴露明确名称、焦点和状态，目标尺寸至少 44 × 44px。
- 状态修改和顺序保存只改任务看板数据，不进入版本图撤销栈，不修改任务与版本的关联、节点父边、分支或放行状态。

### 版本图双向跳转

- 在图的任务聚合模式中，Ctrl/Cmd+左键单击任务节点跳到同项目看板并选中对应内部 `Task.id` 卡片；任务节点普通点击仍执行展开/收起。键盘操作菜单提供等效入口。
- 看板详情列出该任务关联的所有软件版本；没有关联版本时显示明确空状态。点击一个版本跳到同项目版本图，切至全部版本模式以确保目标可见，滚动定位并突出对应版本节点。
- 跳转使用内部 ID/版本节点 ID，不依据可变 Task ID 或版本文本重新查找；导航不更改业务数据。切换项目时丢弃上一项目的焦点目标，目标不存在时明确提示并保留当前页面。

### 页面状态与响应式

- 提供项目无任务、无选项、加载中、保存中、保存失败和空泳道状态；错误不得伪装成保存成功。
- 桌面以可独立横向滚动的泳道区域呈现；任务详情作为独立视图替换看板内容，不使用右侧抽屉。窄屏允许泳道横向滚动，详情页字段和关联信息改为单列，不造成页面整体横向溢出。
- 支持键盘完整操作、可见焦点与 Escape 关闭详情；遵守减少动态效果偏好。正文对比度至少 4.5:1，状态不只靠颜色表达。

## 4. 必要接口与数据

- `Task` 包含可空 `statusOptionId`、`typeOptionId`、`priorityOptionId`、`assigneeId`、`startDate`、`dueDate`，非负 `sortOrder` 和评论数组；评论项包含稳定 ID、Markdown `text`、ISO UTC `createdAt`/`updatedAt`。
- 每个项目保存有序 Status/Type/priority/assignee 选项列表，每项有稳定 ID 与名称；priority 选项另存 `indicatorCount`（1–3）与 `indicatorColor`（`#RRGGBB`）；Task 只保存选项 ID，不保存可编辑名称。
- 新任务默认 Status 引用 `Backlog`；Type/priority/assignee 和日期为 null，评论为空数组。v6→v7 迁移给现有任务写入空看板字段；v7→v8 保留旧 priority 名称/ID、补齐显示属性，并为旧空列表安装默认五档。旧任务全部 Status 置 null，不推断历史状态；任务按名称、再按稳定 ID 排序确定 `sortOrder`。
- Dexie v8/v9 迁移失败需原子回滚；v8→v9 将“最低”置于“较低”之后并保留选项 ID。同一项目 revision 覆盖全部任务字段、评论及选项变更；JSON schemaVersion 5 严格校验优先级标记、选项引用、日期、评论 ID 和内容。
- 配置 JSON schemaVersion 5 覆盖 Status/Type/priority 选项（含感叹号数量/颜色）、Task ID、assignee、日期、评论、任务引用及卡片顺序；不加入文件信息、目录句柄、外部系统链接或同步数据。导入校验所有引用均属于同一项目，评论内容作为不可信文本保存/渲染，不执行 HTML。
- 当前代码 Dexie v6 已用于全局归档根目录；看板字段统一进入 Dexie v9 / JSON schemaVersion 5，v4 快照显式迁移至 v5。若这些版本已发布后才新增字段，必须再提升版本并提供显式迁移，不得在已发布版本中静默改变契约。
- 页面导航状态（当前选中卡片、展开面板、临时高亮）不持久化。Task ID 仍作为字符串保留前导零。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| Task ID 格式非法或同项目重复 | 拒绝保存并提示 1–16 位数字/冲突任务；保留输入 | 用户修正后重试 |
| assignee、日期或 priority 值非法/引用失效 | 按最终确认的 Q-022–Q-024 规则拒绝提交，不静默清空 | 修正字段或重新选择有效选项 |
| 截止日期早于开始日期 | 按 Q-023 最终确认的校验规则提示并保留输入 | 调整任一日期 |
| 评论保存/修改失败 | 保留评论草稿，显示失败状态，不伪装成功 | 重试保存 |
| 删除仍被使用的选项 | 确认前列出影响数量；取消不变，确认后清空对应字段 | Status 显示于“未分组”，Type 显示“未设置” |
| revision 冲突或 IndexedDB 写入失败 | 不部分更新，显示可操作错误；不显示成功状态 | 重新读取项目后重试 |
| 拖动到无效泳道/目标已删除 | 不改变任务状态与顺序，提示重新加载 | 重新读取当前项目 |
| 跨页导航目标已删除/不存在 | 留在当前页并明确提示目标不可用 | 用户重新选择有效任务/版本 |

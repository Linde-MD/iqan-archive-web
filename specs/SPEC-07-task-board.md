- 规格状态：可实施
- 实施状态：核心实现已存在；共享账号负责人与数据迁移正在实施，需完成自动化及浏览器回归后再更新状态
- 范围：核心
- 关联需求：REQ-033、REQ-036、REQ-057
- 真实前置依赖：SPEC-00 任务稳定 ID、项目事务及版本关联契约；SPEC-02 图内任务投影；SPEC-03 JSON 快照契约；SPEC-08 共享账号目录 API 与协作存储迁移
- 未决阻塞：无。Q-022 的负责人规则已由 REQ-057 取代；Q-023–Q-025 已确认。

## 1. 目标

在每个项目中提供独立任务管理页面，按 Status 看板管理任务，并能在任务卡片与关联软件版本图节点之间双向定位。任务支持共享账号负责人、开始/截止日期、可配置 priority 及可修改 comment。启用协作模式时，负责人来自同一 Access 数据库内已启用的非 admin 账号；单人/历史只读模式不提供本地自定义负责人。

## 2. 范围

- 包含：项目入口、Status 泳道看板、任务字段编辑、Status/Type/priority 选项维护、任务评论新增/修改、拖拽与键盘替代操作、版本关联列表及图/看板导航。
- 不包含：Loop 登录、卡片链接、外部读取/同步、跨项目任务、多人协作、版本图关系编辑或 IQAN 文件内容操作。
- Task ID 指现有外部编号字段 `externalTaskId`，显示名称为“Task ID”；内部稳定 `Task.id` 和节点引用 `taskId` 不改变，校验继续沿用同项目唯一、1–16 位 ASCII 数字规则。
- Type 初始名称为 `Project Development`、`Series Maintenance`、`Field / After-sales Support`、`CO Support`、`Bug / Issue`、`Technical Improvement`、`Internal`，用户可在选项管理中改名。数据库 v11 将与旧默认值完全相同的截断名称及 `Bug/Issue` 替换为完整名称，保留选项 ID 和任务引用；若目标名称已存在则保留旧名称以避免重名。其他自定义选项不变。JSON v4–v6 保留快照中的选项原文；无类型选项的 v3 使用新默认值。
- Status 初始选项按截图可辨顺序为 `Backlog`、`Pending`、`In Progress`、`release pending`、`Done`。新增选项追加到末尾。
- REQ-036 的日期、priority 和 comment 规则保持不变；负责人规则由后续 REQ-057 更新为共享账号。日期为可空 `YYYY-MM-DD`，截止不得早于开始；priority 默认包含 `最高`、`较高`、`普通`、`最低`、`较低` 五档，任务默认仍为 null；每项可新增/删除/改名，并设置 1–3 个感叹号及六位颜色。评论为可新增/修改/删除的 Markdown 文本，保存创建/修改时间，不记录作者/修订历史。
- 设计沿用适用于工程工作台的深色控制台 token 与现有响应式组件规范，不采用 UI/UX Pro Max 通用营销页布局。UI/UX Pro Max `dark productivity dashboard kanban --domain style` 命中 `dark-mode-oled` 与 `data-dense-dashboard`；采纳高对比深色、可见焦点、减少动态效果及紧凑但可读的看板布局，不照搬纯黑霓虹或通用分析图表。UX 域“拖动操作需提供单指针替代及完整键盘操作”的指南适用；看板不允许仅靠拖拽操作。

## 3. 功能与交互规则

### 任务详情改版（已确认，部分实施）

当前已实现父任务选择、子任务入口、删除父任务时解除直接子任务及 Dexie v11 / JSON schemaVersion 6 迁移，并实现详情字段重排、任务字段自动保存和评论/关联版本侧栏切换。任务说明和评论共用支持直接编辑富文本、Markdown 源码及预览的编辑器（REQ-061）；保存格式仍为 Markdown。以下 REQ-036 / Q-025 / AC-13 的无作者规则仅描述旧版，协作评论以「评论协作与回复」为准，原验收须复核。

- 参考用户提供的 Worktile 截图的信息层级，保留本产品深色工程工作台视觉、中文标签、键盘操作和响应式布局。左上角显示可编辑外部 Task ID 与父任务，名称在下方独立显示并可悬停/聚焦编辑；移除无用的顶部英文提示。已有任务的 Task ID 可空，继续遵循项目内唯一及数字格式规则。
- 桌面首行排列负责人、状态、开始日期和截止日期；另一行放置优先级、Type 等其他字段。负责人用账号上传头像或稳定 initials/颜色显示；移除按钮在悬停、键盘焦点和触屏下可用。不同状态以对应图标和可读文字共同表达，并应用于详情、卡片和列表。窄屏按可用宽度换行，字段保留可访问标签。
- 优先级的已选值以配置颜色显示感叹号，名称保持正文颜色；日期非编辑状态统一显示年-月-日格式，编辑时保留浏览器原生日期选择器，其界面语言由浏览器决定。
- 已创建任务的文本字段失焦后自动保存，下拉和日期变更后自动保存，描述停止输入一段时间后自动保存；保存中、成功、失败及修订冲突明确反馈。输入期间和保存失败时保留草稿，避免异步保存覆盖后续输入。新任务先填写有效名称并显式创建，成功后使用自动保存。
- 同一项目的任务可设置至多一个父任务及多个子任务，形成树形关系；禁止自关联、循环及跨项目关联。详情可设置/解除父任务、查看并打开子任务；删除父任务前说明影响，确认后解除其直接子任务的父关联，不删除子任务。任务层级不隐式修改版本图、放行或看板状态。
- 主区域提供“任务信息”和“子任务”标签切换；任务信息展示优先级、类型及说明，子任务标签展示并打开直接子任务。切换只影响视图，不清空任务或评论草稿。
- 父子关系需要数据库和 JSON 快照显式版本迁移；既有任务默认为无父任务，旧快照导入后保持原数据，新快照包含完整关联。新版本需验证旧数据升级、导入导出往返、内部 ID 重映射、引用和成环校验及事务失败回滚；新版快照不承诺可被旧应用读取。
- 任务说明和评论复用 ProseMirror（MIT）编辑器的格式工具栏、富文本、Markdown 源码与预览。支持下划线、删除线、代码块、复选清单、表格和链接；不能无损切换的内容保留原文，并提示使用源码。已有任务说明有改动才在编辑框边框外的右下方并排显示“取消 / 保存”：取消为文字按钮，保存为紧凑蓝色按钮；不随输入、切换模式或其他字段自动保存。新建任务随创建提交。评论仍显式提交。原始 HTML 不执行，Markdown 图片不加载，富文本仅接收纯文本粘贴。
- 评论富文本工具栏保持单行；常用格式优先显示，空间不足时其余工具收进「更多格式」菜单。
- REQ-062：说明下方以紧凑元数据行显示「头像 姓名 创建于 时间｜姓名 更新于 时间」，同一账号只显示一次头像，不同账号各显示头像，窄屏可换行。新署名保存账号 ID，用于从现有成员目录或当前登录资料读取头像，不把图片写入项目快照；无可用头像时显示名字缩写，不按姓名猜测账号。协作后端以当前登录账号及服务端时间在同一提交内写入：创建任务记录创建人；已有任务的说明实际变化才记录最后编辑人，改名、改状态、改负责人、评论和取消均不更新。无历史数据时显示“未记录”，不补写创建人。署名保留操作时名称，账号改名或删除不抹除记录。备份导入和撤销/重做按快照恢复历史署名，不把执行恢复的人填为作者。旧快照可省略署名及账号 ID 字段；发布时同时升级网页与后端。
- 共用编辑器采用一体式边框、内嵌分组图标工具栏和右上角模式菜单；可增大正文区，长内容在编辑区内部滚动，不改变保存方式。

### 项目入口与看板

- 每个项目入口并列显示“管理文件”“版本分支图”“任务管理”三个图标按钮，均有可访问名称、可见焦点及当前选中状态；选择任务管理进入该项目独立看板页。
- 任务管理默认显示看板，也可切换为工作项列表；列表以表格显示编号、标题、状态、负责人、父任务、类型、优先级及日期，点击标题打开已有详情。两种视图共享搜索和任务数据，切换不改变任务、看板顺序或父子关系。
- 当前项目提供“全部任务 / 我负责的任务”范围切换，默认全部；个人范围仅在登录验证后可用，按当前账号 ID 匹配 `Task.assigneeId`，不跨项目汇总，不改变新建任务的负责人。看板和工作项列表共享范围，并与现有搜索取交集；未登录或账号变化恢复全部。嵌套列表允许显示标注“上级”的非匹配祖先，不计入结果；从版本图显式定位被筛掉的任务时，只放宽阻挡定位的筛选。不修改数据或权限。
- REQ-058 验证：任务相关 35 项测试及生产构建通过。隔离浏览器预览验证本人范围、嵌套上级上下文、搜索交集、定位不匹配任务及 375×812、812×375 布局；范围按钮高 44px，页面无横向溢出。未使用团队业务数据。
- 列表可开关父子嵌套：开启时顶层包含所有无父任务的任务（包括没有子任务的独立任务），父任务默认折叠，可逐级展开；关闭时全部任务平铺。各层分别按外部 Task ID 的数值从大到小排序，无编号排最后；数值相同时按原始编号、任务名和内部 ID 稳定排序，不能丢失 16 位精度。
- 两种列表均应用现有搜索；嵌套模式搜索命中时显示匹配任务及其祖先并自动展开祖先路径，允许用户手动折叠；计数表示匹配任务数量，不包含为上下文显示的祖先。清空搜索恢复先前手动展开状态。视图、嵌套和展开状态仅属于当前页面会话。
- 看板默认按 Status 分列泳道，列顺序采用选项顺序；无 Status 的任务显示在单独的“未分组”泳道。“未分组”当前可见任务数为 0 时隐藏，有未设置状态且符合筛选的任务时自动重新显示；其他 Status 泳道保留空泳道。未分组泳道正在快捷新建时保留表单，避免任务变化导致草稿入口消失。Type 作为任务属性，不作为默认分列字段。
- 每个泳道在可视区域底部固定“添加新任务”入口，空泳道与长泳道均始终可见，卡片列表独立滚动。点击后在底部展开简洁新建表单，仅输入任务名并确认或取消；创建时自动分配当前项目最大 Task ID 加一，创建后留在看板，状态为该泳道并追加到该泳道末尾。编号达到上限时保留输入并提示使用完整新建任务表单手工填写未使用的编号。保存失败或项目修订冲突保留输入，冲突后需重新读取才能重试，并根据最新数据重新计算编号。搜索不会改变编号计算或追加位置，新任务不匹配筛选条件时明确提示。
- 看板搜索可选择 Task ID、关键字或负责人模式；关键字匹配任务名和说明，负责人按共享账号显示名或用户名匹配。Task ID 支持精确文本匹配或 `起始-结束` 闭区间匹配，范围端点均为 1–16 位数字并按数字字符串比较，不丢失 16 位精度；精确匹配保留前导零。非法格式或起始值大于结束值时明确提示，不匹配任务。
- 负责人选择器从已认证的共享账号目录读取；仅列出 `role=member && disabled=false` 账号，选项以显示名和用户名区分。后端对每次新增/变更负责人再次校验，不信任前端提供的 ID；不得选择 admin、停用账号或不存在账号。账号目录读取失败时禁用负责人控件并保留其他任务草稿，不将失败当作“暂无成员”。
- 账号停用后，已有任务仍保留该账号 ID 并显示“已停用”，允许清除或改派；目录接口需向已认证用户返回非 admin 成员的最小展示字段（ID、用户名、显示名、头像及停用状态）。头像只接受服务端验证的 PNG data URL，不加载外部图片地址。项目、看板卡片和列表均按共享账号 ID 显示负责人；搜索可匹配显示名和用户名。
- 删除旧项目 assignee 选项后，选项管理只维护 Status/Type/priority，不再允许新建负责人选项。兼容保留的 `Project.assigneeOptions` 必须为空，不得作为负责人目录或写入入口。
- 每张卡片可见 Task ID（有值时）、任务名、Status 和 Type；长说明在详情中查看。卡片不显示独立拖动按钮，卡片非按钮区域通过指针移动启动拖动；点击卡片打开大尺寸模态详情窗，底层看板保留。桌面详情窗左侧显示任务字段和说明，右侧切换评论及关联软件版本；窄屏使用全屏模态并纵向排列。详情含 Task ID、任务名、Status、Type、Description、删除操作、版本入口及评论；关闭、Escape 和浏览器后退遵循未保存草稿保护。上移/下移按钮继续提供拖拽以外的排序操作。
- 任务名必填，Description 可空。新建任务的 Task ID 必填，完整新建表单打开时按本项目全部已有编号的数值最大值加一预填，泳道快捷新建则在确认时自动分配；没有编号时为 `1`，忽略前导零进行比较，结果不带前导零。完整表单可手工修改为未使用的 1–16 位数字；最大值为 `9999999999999999` 时明确提示无法自动编号，要求在完整表单手工填写未使用的编号。重复、非法或空编号不得创建；并发修改遵循 revision 保护并保留草稿。已有任务可继续清空编号，旧数据及 JSON 导入兼容不变。新建任务默认 Status 为 `Backlog`，Type 可不选。Status/Type 每项至多选择一个选项；未设置 Type 显示“未设置”。
- 任务创建、编辑、删除及选项维护遵循项目 revision 并发保护。删除任务前说明并确认：删除任务记录及评论，解除版本节点的 `taskId` 和直接子任务的父引用，不删除子任务，不改版本、父边、分支和放行状态。

### 新增任务字段与评论（REQ-036）

- 任务编辑面板应支持分配/清除 assignee、设置开始日期和截止日期、设置 priority，并查看该任务的评论列表。
- 评论支持新增、修改和删除；使用 Markdown 文本与安全渲染，保存 ISO UTC 创建/修改时间，不记录作者或修订历史，不加载图片。
- 看板卡片应以适合密集泳道的摘要呈现已设置的 assignee、priority 与日期；具体显示字段和日期格式须与最终数据规则一致，并在桌面/窄屏验收中避免卡片溢出。
- 开始日期、截止日期均可空；日期是否为本地日历日期或时间戳、以及截止早于开始时的处理由 Q-023 确认。priority 选项可由用户配置；初始选项、默认值、顺序及删除被引用选项的行为由 Q-024 确认。
- REQ-057 更新了原负责人方案：协作模式下 `Task.assigneeId` 是共享账号稳定 ID；本地自定义负责人选项不再提供。
- `Task.assigneeId` 保存共享数据库中的稳定账号 ID，不保存用户名、邮箱或项目选项 ID。JSON schemaVersion 8 保留账号 ID；旧 schemaVersion 3–7 的导入迁移清空负责人选项和任务分配。跨数据库恢复时若账号 ID 不属于目标库或已停用，服务端拒绝该新增/变更负责人，恢复文件不得隐式创建账号。
- 数据迁移按单个协作数据库处理：Access schema 4→5 清空所有项目负责人选项和任务 `assigneeId`，受影响项目 revision 增加一次；主 Dexie v13→14 清空历史本机项目相同字段并推进其 revision；协作 Dexie v1→2 清空镜像旧负责人并保留草稿。不可变 pending 请求无法改写，若仍存在，协作缓存升级须明确拒绝；部署前须在旧版中处理完未确认提交。
- 日期控件使用本地日期输入，不转换 UTC 日期；非法日历日期和截止早于开始均拒绝，保留草稿并明确提示。
- 评论列表按创建时间从旧到新排列；每条评论提供查看、编辑和删除，删除前确认；渲染使用安全 Markdown，不执行原始 HTML、不加载图片。创建/修改时间以 ISO UTC 保存，不显示作者，不保留编辑历史。评论单条长度不另设上限，完整 JSON 仍受 SPEC-03 20 MiB 限额约束。

### 选项维护

- Status 与 Type 选项在当前项目内分别维护，支持新增、重命名、删除；新增项按添加顺序显示，重命名保留选项稳定 ID 与现有任务引用。
- 删除选项若仍被任务使用，先明确显示受影响任务数量并要求确认。确认后删除选项并将这些任务的对应字段清空；不自动迁移到其他选项。Status 清空后任务进入“未分组”泳道；Type 清空后显示“未设置”。
- 选项名称去除首尾空白且不能为空；同类选项名称不可重复。失败保留输入、明确指出原因，不能部分修改。
- priority 默认选项按 `最高`（!!!、`#f05252`）、`较高`（!!、`#f27ba5`）、`普通`（!!、`#eabf35`）、`较低`（!、`#35b8ed`）、`最低`（!、`#20bfa9`）初始化；任务默认 priority 为 null。用户可新增、重命名、删除选项，并编辑 1–3 个感叹号和颜色；删除被使用的 priority 选项前确认，确认后清空引用。卡片左边线显示优先级颜色，感叹号越多边线越粗；优先级名称保留可访问文本。

### 拖动与可访问替代

- 拖拽卡片靠近当前泳道卡片列表的可视顶部/底部（48px 边缘区）时，即使指针保持不动也持续向对应方向滚动，越靠近边缘越快；仅滚动指针所在泳道的卡片列表，保留标题和底部添加入口。移回中间、离开泳道、到达滚动边界或结束/取消拖拽即停止；切换泳道时只滚动新目标，卸载时清理动画帧。保留看板横向拖拽滚动及键盘替代，滚动后的预览与最终保存位置一致。
- 垂直边缘判断使用真实鼠标/触摸坐标，不使用拖拽库滚动补偿产生的合成位移；官方 `DragOverlay` 独立渲染拖拽浮影，避免滚动后占位符恢复覆盖 Vue 管理的卡片顺序。直接声明同版本的 `@dnd-kit/dom` 以配置已有 AutoScroller 仅保留横向自动滚动，不引入第二套拖拽运行时。

- 卡片拖到另一 Status 泳道的空白处或其他卡片上，均按指针释放所在泳道更新其 Status；在同一泳道内拖动只改变该泳道顺序。提交原子持久化，刷新后状态/顺序不变；跨项目、失效选项或 revision 冲突时整体拒绝并显示错误。
- 拖拽采用受控任务预览：泳道、位置及卡片 Status 标签由同一份投影数据驱动，各泳道使用独立拖拽分组及组内索引，禁止拖拽库仅移动 DOM 而不更新投影。放下时提交最后可见预览的位置，不再根据旧碰撞目标重新推断；包括目标为卡片自身、跨泳道卡片前后、空泳道及筛选下的排序。取消/无落点不写入；保存失败或 revision 冲突时撤回预览并明确反馈，不保留成功外观。
- 使用官方 `@dnd-kit/vue` Vue 适配包，不引入 React。适配包要求 Vue 3.5+，仓库 `package.json` 声明的 Vue `^3.5.44` 满足版本范围；实施时仍须用 npm 锁定实际版本并按 package metadata 核实许可证与依赖。该包要求拖放 hooks 位于 provider 的后代组件中。
- 拖拽必须有键盘和单指针非拖拽等效操作：提供“移至”状态菜单/按钮及卡片上移、下移操作；拖拽不是唯一输入方式。拖动/菜单/按钮均暴露明确名称、焦点和状态，目标尺寸至少 44 × 44px。
- 状态修改和顺序保存只改任务看板数据，不进入版本图撤销栈，不修改任务与版本的关联、节点父边、分支或放行状态。
- 新建任务及通过详情修改 Status 时，由领域层将任务追加至目标泳道末尾；与拖拽、删除一致，在同一项目事务中将泳道顺序压紧为从 0 开始的连续序号。普通字段编辑保留卡片相对位置；兼容已有不连续序号，不使用任务数量直接覆盖未整理泳道中的位置。外部 Task ID 不受顺序整理影响。

### 版本图双向跳转

- 在图的任务聚合模式中，Ctrl/Cmd+左键单击任务节点跳到同项目看板并选中对应内部 `Task.id` 卡片；任务节点普通点击仍执行展开/收起。键盘操作菜单提供等效入口。
- 看板详情列出该任务关联的所有软件版本；没有关联版本时显示明确空状态。点击一个版本跳到同项目版本图，切至全部版本模式以确保目标可见，滚动定位并突出对应版本节点。
- 跳转使用内部 ID/版本节点 ID，不依据可变 Task ID 或版本文本重新查找；导航不更改业务数据。切换项目时丢弃上一项目的焦点目标，目标不存在时明确提示并保留当前页面。

### 页面状态与响应式

- 提供项目无任务、无选项、加载中、保存中、保存失败和空泳道状态；错误不得伪装成保存成功。
- 桌面以可独立横向滚动的泳道区域呈现；任务详情使用覆盖式模态窗口，不替换看板，也不使用右侧抽屉。窄屏允许泳道横向滚动，详情模态全屏显示并纵向排列字段与评论区，不造成页面整体横向溢出。
- 支持键盘完整操作、可见焦点与 Escape 关闭详情；遵守减少动态效果偏好。正文对比度至少 4.5:1，状态不只靠颜色表达。

## 4. 必要接口与数据

- `Task` 包含可空 `statusOptionId`、`typeOptionId`、`priorityOptionId`、`assigneeId`、`startDate`、`dueDate`，非负 `sortOrder` 和评论数组；评论项包含稳定 ID、Markdown `text`、ISO UTC `createdAt`/`updatedAt`。
- 每个项目保存有序 Status/Type/priority 选项列表；负责人选项字段仅为旧快照兼容并始终为空。priority 选项另存 `indicatorCount`（1–3）与 `indicatorColor`（`#RRGGBB`）；Task 保存账号 `assigneeId`，不保存负责人可编辑名称。
- 新任务默认 Status 引用 `Backlog`；Type/priority/assignee 和日期为 null，评论为空数组。历史 v6→v7、v7→v8 priority 迁移规则保持不变；v7→v8 同时清空旧负责人选项和分配。旧任务全部 Status 置 null，不推断历史状态；任务按名称、再按稳定 ID 排序确定 `sortOrder`。
- Dexie v8/v9 迁移失败需原子回滚；v8→v9 将“最低”置于“较低”之后并保留选项 ID。同一项目 revision 覆盖全部任务字段、评论及选项变更；JSON schemaVersion 8 严格校验优先级标记、选项引用、账号负责人 ID、日期、评论 ID 和内容。
- 配置 JSON schemaVersion 8 覆盖 Status/Type/priority 选项（含感叹号数量/颜色）、Task ID、账号 assignee ID、日期、评论、任务引用及卡片顺序；不加入文件信息、目录句柄、外部系统链接或会话。v3–v7 导入显式清空旧项目负责人选项/任务分配；v8 的账号负责人由服务器按目标数据库账号验证。评论内容作为不可信文本保存/渲染，不执行 HTML。
- 当前主库为 Dexie v14、项目 JSON schemaVersion 8；历史 Dexie v13→14 清除旧负责人选项/分配，JSON v7→v8 清除旧负责人数据。旧 schema 的具体演进见 SPEC-03；后续数据字段变化必须继续显式升级并迁移，不得静默改变已发布契约。
- 页面导航状态（当前选中卡片、展开面板、临时高亮）不持久化。Task ID 仍作为字符串保留前导零。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| Task ID 格式非法或同项目重复 | 拒绝保存并提示 1–16 位数字/冲突任务；保留输入 | 用户修正后重试 |
| assignee、日期或 priority 值非法/引用失效 | assignee 必须是启用的非 admin 共享账号；日期/priority 按 Q-023–Q-024 校验，不静默清空 | 修正字段或重新选择有效值 |
| 截止日期早于开始日期 | 按 Q-023 最终确认的校验规则提示并保留输入 | 调整任一日期 |
| 评论保存/修改失败 | 保留评论草稿，显示失败状态，不伪装成功 | 重试保存 |
| 删除仍被使用的选项 | 确认前列出影响数量；取消不变，确认后清空对应字段 | Status 显示于“未分组”，Type 显示“未设置” |
| revision 冲突或 IndexedDB 写入失败 | 不部分更新，显示可操作错误；不显示成功状态 | 重新读取项目后重试 |
| 拖动到无效泳道/目标已删除 | 不改变任务状态与顺序，提示重新加载 | 重新读取当前项目 |
| 跨页导航目标已删除/不存在 | 留在当前页并明确提示目标不可用 | 用户重新选择有效任务/版本 |

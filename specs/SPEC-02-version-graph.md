- 规格状态：框架
- 实施状态：部分（Git Graph、图命令、当前会话撤销/重做、任务管理、版本任务关联与 Loop ID 编辑/详情已实现并抽查；任务聚合双模式、聚合标题中的 Loop 展示及双版本对比未实现；完整验收仍待补齐）
- 范围：核心
- 关联需求：REQ-003–REQ-006、REQ-010–REQ-017、REQ-020
- 真实前置依赖：SPEC-00 的版本图领域契约；可与 SPEC-01 并行完成图形交互原型
- 未决阻塞：原 Q-002/003/004/010/011/018 已由第八轮解决，Q-008 已解决；本规格仍待图布局选型与交互细化，不因基础命令存在自动标为已实施。协议细节归 SPEC-04/05。

## 1. 目标

让用户在每个项目中一眼查看版本历史，并安全编辑节点、分支和合并关系；图表展示版本关系，不暗示它能修改或合并 IQAN 文件内容。

## 2. 范围

- 包含：项目版本图；节点增改删与分支/合并；纵向 Git Graph 排列、局部滚动和锚点缩放；分支筛选、分支头名称、分支信息与颜色；可选任务关联和双模式；节点及全祖先放行；扁平图标控件与图操作撤销。
- 不包含：Web 内部文件 diff、二进制内容 merge、Git 仓库互操作、协作和权限管理。新增的 IQANdesign 外部对比入口转交 [SPEC-04](./SPEC-04-iqandesign-integration.md)，不代表前端已具备内容对比引擎。
- 已确认节点呈现：展开的版本节点直接显示版本号，不显示软件零件号；改动信息在鼠标悬浮或键盘焦点时显示。任务聚合模式按新需求允许隐藏任务内部节点，澄清了原“始终显示”的范围。
- 交互约束：图以有向关系展示，阻止循环；不提供节点拖拽或画布拖拽平移，父边通过可搜索的版本选择控件修改；键盘与触屏可用选择、菜单和表单完成操作。
- 样式依据：适合桌面工程工具、图形画布和实际技术栈的 UI/UX Pro Max 建议为主，[DESIGN.md](../DESIGN.md) 为辅助参考；当前采用深海军蓝工程控制台、冷蓝交互色、分层深色面板及系统中文字体。明确用户要求、产品规则与无障碍约束优先，不照搬霓虹效果或营销页布局，见 DEC-003/REQ-025。

## 3. 功能与交互规则

### 批量父子关联

- 选择至少两个版本后，工具栏及多选右键菜单提供“清除父子关联”：移除任一端属于所选版本的全部直接父边（包括与未选版本的关系），不删除节点，不自动重连，不更改分支指针、任务或放行状态。
- 所选版本全部无任何入边、出边时，提供“构建线性关联”：使用现有完整版本号比较规则从旧到新生成相邻父子边，较旧为父、较新为子，与点击顺序、当前图排序无关。不关联未选版本，不创建或推进分支。
- 两种操作均在右侧操作面板列出受影响父→子关系，确认后单事务提交，取消不修改。预览绑定项目修订号；并发更新后要求重新预览，事务仍检查 revision。作为单个命令支持当前会话撤销/重做。
- 严格遵守已放行子版本父边锁定，包含未选中的子版本；不能部分成功。线性链允许已放行游离版本作为根，但不得新增已放行版本的父边。无关联可清除、非游离选择或非法选择明确提示。
- 验证（2026-11-03）：批量关联与既有图编辑共 16 项测试通过，覆盖自然版本顺序、外部边清除、非法选择、放行锁定、事务回滚、修订冲突及撤销/重做恢复；生产构建含类型检查通过。生产预览用临时项目验证反序显示和离散多选下仍按旧→新预览/构建、已有边时禁用线性关联、取消清除保留原边、确认清除、撤销及 Ctrl+Y 重做；375px 下预览完整位于视口、标题获焦。操作事件部分由 DOM 分派，完整真实键盘/触屏流程仍待实机验证；临时项目已清理。

- **分支筛选**：使用带名称搜索的复选框下拉列表，支持任意多选且勾选时保持展开；所选分支头及全部祖先取并集，共享祖先不重复，游离版本列默认保留、可独立隐藏。“显示全部”恢复全部分支范围但不重置隐藏开关，“全不选”仅显示未隐藏的游离版本；搜索不清除未匹配项的选择。支持键盘 Tab/Space、Escape 关闭回到触发器及点击外部关闭。筛选仅改变投影，不修改版本图、分支头或任务归属。
- **滚动和缩放**：图内普通滚轮上下滚动；Shift+滚轮左右滚动；Ctrl+滚轮以光标位置为锚点缩放，并保留缩放按钮。缩放不得自动 fit 长图或令首行无法滚动到；排序切换不得改变画布首行的可达性。图外滚轮仍按页面默认行为工作。
- **排序**：可切换旧→新/新→旧。父子拓扑优先于版本号排序，父子约束冲突时不可为满足版本比较而颠倒父子行；排序只影响显示。
- **父版本选择**：新增、合并及设置父版本统一采用单行“可输入下拉框 + 添加”控件。点击输入框内的下拉箭头展开候选，按完整版本号比较，将临近候选优先展示；输入内容按版本号或说明过滤，不改变推荐顺序。选择候选后点击“添加”才进入已选父版本列表，输入任意文本不能直接添加；添加后清空输入并排除已选版本。提供无匹配提示、方向键浏览、Enter 选择、Escape 关闭下拉及可见焦点。不得选择自身或其后代；保存仍使用相同的放行锁定、环检测和项目修订事务。
- 新父边操作不自动改变分支头、放行状态、版本号或工程文件。
- 节点改动说明通过悬浮与键盘 focus 查看；移动设备无 hover 时提供点击查看。说明需可被辅助技术感知，长文本不能被永久裁切。
- 支持显式多选版本，右键已选节点不破坏已有选择；多选可用于新建合并版本和批量删除（删除前必须预览关系重连及分支头处置）。放行仅作用于单一版本或明确选择的分支，不将单节点命令隐式作用于多选。两个版本的 IQANdesign 对比及 A/B 预览仍交由 [SPEC-04](./SPEC-04-iqandesign-integration.md) 定义。

### 编辑

### 任务关联与双模式

- 任务管理首批 UI：工具栏“任务管理”在右侧面板提供名称/Loop ID 搜索、创建、编辑及删除确认；任务列表显示完整名称、说明、Loop 编号和关联版本数量，独立限高滚动。删除仅解除版本任务关联，保留版本、父边、分支与放行。
- 新增版本、创建合并版本及编辑版本均提供“所属任务”单选，可为空；已放行版本仍可修改任务归属。选中版本详情区区分“未关联任务”及有任务但“未关联 Loop”。任务表单复用 Loop 长度、归一及同项目唯一性校验，失败保留输入；任务编辑/删除绑定打开时 revision，陈旧修订不覆盖新数据。命令接入当前项目撤销/重做。
- 本批仅接入任务管理、Loop 编辑/展示和版本关联，不代表任务聚合布局/双模式已实现；AC-09/10/15 的完整验收仍保持未勾选。
- 验证（2026-11-03）：领域/存储与图编辑共 33 项测试、生产构建及类型检查通过。新增任务删除事务测试覆盖已放行节点解除关联、图结构保留、非法 ID/修订冲突回滚及撤销恢复。生产预览验证创建任务、Loop 重复/17 码点拒绝并保留输入、版本任务选择与详情、清空 Loop、删除预览及确认、撤销恢复任务及原关联；375px 下表单在独立面板滚动且无整体横向溢出。部分交互采用 DOM 事件，完整真实键盘/触屏及全屏流程未验。

- 每个节点可不关联任务，或关联一个同项目任务；同任务可关联多个版本，不强制每个版本属于任务。
- **任务聚合模式**：任务作为外层对象显示；选择任务或双击任务可展开其具体版本节点；键盘 Enter/Space 提供等效展开，并显示展开状态。任务不等于一个真实版本节点。
- **全部版本模式**：直接展示全部版本节点，不要求先选择任务，恢复版本号通览。未关联任务的节点在两种模式都应可达、可见。
- 切换模式和展开/折叠只改变显示，不增删实际节点/父边、变更分支头、改写任务归属或放行状态。
- 允许跨分支/非连续任务；以容器展示，不压缩成单个任务图节点，保留真实节点端点/连线映射，不按组顺序推断父边。
- 隐藏分支头有摘要/展开入口；基础投影返回组内 node IDs 和分支头记录，具体布局仍需本阶段实现。
- 任务名称必填、说明和 Loop ID 可空；确认删除任务仅解除节点关联。初始全部版本模式，展开状态不持久化，切换不算编辑历史。

### Loop 任务编号展示与编辑（REQ-020）

- 结构沿用 [SPEC-00 的任务与 Loop 关联](./SPEC-00-foundation.md)：版本节点仍引用内部 `taskId`，Loop ID 保存于任务对象，不在每个版本节点复制一份。
- 展示方案：任务聚合容器标题区常显任务名称与带“Loop”标识的编号，例如 `Loop 1479-1 · 修复转向逻辑`；名称为示意，不从远端读取。展开/折叠均保留关联标识，不只在 hover 中显示。
- 全部版本模式不强制在每个节点常显 Loop 编号，保留版本号的视觉优先级；选中节点后的详情区域展示“所属任务：名称 / Loop ID”。任务详情或编辑区域显示完整编号；无所属任务显示“未关联任务”，有任务无编号显示“未关联 Loop”，二者不可混淆。
- 任务编辑入口提供可见的“Loop ID”标签、`1479-1` 示例及同项目唯一/手工映射说明；可添加、修改或清空编号。任务选择列表以名称和 Loop ID 辅助区分，实际选中值始终是内部任务 ID。
- 冲突/非法输入保留输入并明确反馈，不合并任务/重绑节点。Q-018 已确认：任意文本、去首尾空白、区分大小写、空为 null、最多 16 个 Unicode 码点，同项目唯一；不按示例限定数字正则。
- 长编号/名称避免撑宽画布或遮挡版本号、分支头和放行状态；紧凑编号尽量单行，无法完整显示时可截断，但完整值必须通过键盘可达的详情入口及点击查看，不能仅靠 hover/title。窄屏详情可换行，保留可见焦点与至少 44 × 44px 的主要交互目标。
- 编号按文本显示，不转成超链接；首版不提供“打开 Loop”、链接输入、登录、自动读取/同步、状态映射或远端存在性检查。不因填写编号显示“已同步/已验证”等误导状态。

### 放行

- 真实版本节点有“已放行/未放行”两种状态。未明确初始化状态的旧配置须经版本化导入/迁移规则处理，不能静默猜测既有节点已放行。
- 在节点右键菜单选“放行”；键盘上下文菜单/更多操作入口可执行同一命令。折叠任务不提供含义不明的“整任务放行”。
- 计算真实父图上目标节点及全部可达祖先的集合，沿所有父边递归，包含合并来源链，去重并终止于根。不沿子边放行后代、兄弟或无关分支。
- 建议提交前列出本次新增放行节点与数量，确认后通过 Dexie.js 事务原子提交。已放行祖先不重复改变；重复放行同一节点保持幂等。
- 遇循环、缺失父节点或跨项目边时整体拒绝并明确反馈，不能“部分成功”。失败不改变既有状态。
- 放行与未放行用标记/文字/边框等样式区分，保留独立分支颜色；选择/hover 样式不能盖掉放行状态。
- Q-011 已确认并于 2026-10-30 修订：记录放行时间不记人员；禁止编辑已放行版本号/父边，可改说明/任务。本地文件独立维护，不锁定、无持久化快照。单独撤销若有已放行后代则拒绝，不回撤祖先；结构修改须先撤销。已放行删除按上文额外确认与子节点锁定规则处理，不通过删除绕过锁定。

### 控件与右键菜单

- 当前项目会话内 Ctrl/Cmd+Y 重做最近撤销的图命令，支持连续撤销/重做；沿用快照恢复与 revision 事务保护。成功执行新图命令后清除重做记录，切换项目或修订冲突时清除撤销/重做记录；输入框内不接管文字重做。重做恢复原命令结果（含原放行时间），不重新生成节点身份或时间。
- 重做验证（2026-11-02）：生产构建（含类型检查）、79 项测试及差异检查通过。生产预览经 DOM 快捷键事件分派验证连续两次撤销、两次重做、交替撤销/重做、新命令清空重做及输入框内不接管图重做；刷新后最终节点持久化。测试项目及临时服务已清理。跨标签页冲突与真实键盘组合键本轮未进行浏览器实测。

- 按用户要求优先扁平化、同一图标家族；操作按钮有可访问名称与可见 focus，图标需可理解，必要时保留文字，不把所有按钮强制为无标签图标。
- 工具提示须支持 hover/focus，控件暴露适用的 pressed/expanded/disabled/loading 状态；主要触摸目标至少 44 × 44px。
- 自定义菜单支持方向键、Enter、Escape、焦点回到触发节点，以及触屏/更多操作替代入口。
- 单个版本的右键菜单提供“创建分支”，以该版本作为新分支头，打开右侧分支表单并聚焦名称；复用工具栏的创建流程，已放行版本也可作为分支头。多选版本时仍仅提供合并与批量删除，不隐式选取其中一个版本创建分支。

## 4. 必要接口与数据

- 读取图：项目 ID → 节点、关系、分支头、改动说明和可选布局。
- 节点变更：新增/编辑/删除命令 → 成功结果或包含被引用对象的明确冲突。
- 关系变更：创建分支/建立父子或合并关系 → 校验结果；拒绝循环及不存在的节点引用。
- 视图层读取领域图后布局渲染；图形库内部状态不作为唯一历史数据来源。
- 分支头建议由显式 branch 记录和 head node ID 表示，而不是仅从线条颜色推断；最终契约受 Q-003 约束。
- 版本号、零件号和文件元数据分开；零件号仅显示在项目上下文，不写入节点标签。
- 分支更新输入 branch ID、名称、颜色及确认的其他字段，可显式提交 headId；省略 headId 时保留原头，提供时校验为同项目现有节点。
- 任务关联命令输入 node ID、可空 task ID；视图投影输入原始图和模式，输出可展开任务/版本视图及真实边映射。
- 任务元数据编辑输入内部 task ID、名称及可空 `loopId`，遵循 SPEC-00 项目内唯一性；投影及详情通过 task ID 读取同一任务，不以 Loop ID 取代引用，不为此调用启动器。
- 放行命令输入 node ID，输出目标加全祖先的变更集合；图校验与状态更新在一致数据快照上执行，并原子持久化。

## 10. 实施后验收记录

### 样式方案（对应 DEC-003 / SPEC-02-AC-16）

- 检索模式：UI/UX Pro Max `--design-system --density 8 --motion 3` 的工程图关键词结果包含不适用的营销/FAQ 页面结构；按技能契约改用 `--domain style` 的窄查询 `dark mode engineering dashboard`，命中 active `dark-mode-oled`。只采纳深色高对比、低发光、可见焦点与减少动态效果要求，不照搬霓虹色、黑底营销页或推荐组件。Vue 栈检索无匹配结果，不据其生成栈专属建议。
- 采用方案：全局深色工程工作台（画布 `#0b1120`、面板 `#121c2d`/`#18253a`、正文 `#eef4ff`、次要正文 `#afbdd2`、主操作 `#1d4ed8`、焦点 `#7dd3fc`）；中文使用系统字体，版本/路径使用等宽字。项目侧栏、文件卡片、图表、菜单、表格和反馈状态共用同一语义色阶。节点/关系仍用自绘 SVG；放行状态同时显示文字，分支颜色不承担唯一状态含义。
- 动效：使用 Vue 内置 `Transition`/`TransitionGroup` 和 CSS 的短列表/反馈/表面过渡及节点状态过渡，不新增运行时依赖；关闭减少动态效果偏好下的非必要运动，不使用自动轮播、视差或滚动劫持。
- 对比度及界面检查（2026-11-02）：正文/主面板 15.47:1、次要正文/主面板 8.97:1、主按钮文字/按钮底色 6.70:1、焦点环/画布 11.29:1；浏览器检查桌面/375px 图与节点详情、右键菜单和菜单键盘焦点。减少动态效果偏好下动画/过渡时长为 `0.00001s`。分支色仅作辅助标识，节点内常显放行文字，控件边界/键盘焦点独立可辨。DESIGN.md 为实现 token 映射，不覆盖已确认产品规则。

### 节点标签可读性（对应 SPEC-02-AC-18）

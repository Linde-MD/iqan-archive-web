## 1. 目标与边界

在用户 Windows 电脑上安装一个按需启动的小程序，注册自定义 URI 协议，由 Windows 激活后校验请求、显示确认并调用 IQANdesign。

- 不是 HTTP 后端或常驻服务：不监听 HTTP/WebSocket 端口、不轮询网页、不依赖云端。
- 用户不安装启动器也能使用 GitHub Pages 上的项目管理、版本图、任务、放行和 JSON 备份。
- 当前工程草案仅支持 `open`、`compare`，不支持任意程序执行、通用文件管理、报告生成或自动上传。第九轮新增受限软件对比文档原文件打开规划，见下述后续扩展；未冻结前不能把软件对比文档路径传入工程操作。

### 后续软件对比文档打开扩展（2026-10-30）

用户确认需要打开软件对比文档，首版格式为 `.doc/.docx`，后续使用本机 Word 打开原文件；SPEC-01 仅列文件，无直接打开入口。业务名称不以格式或打开程序命名。Launcher [LSP-04](../../iqan-archive-launcher/specs/LSP-04-word-opening.md) 负责后续实施，保留既有规格路径和编号。

协议仍以本 SPEC 第 3 节为唯一权威。未来须显式区分工程/软件对比文档操作与目录角色，独立配置本机软件对比文档根目录和 Word 程序、逐次确认、最终路径防护；禁止通用 shell 文件关联和网页指定 EXE/参数。具体操作名、版本/编码和 Word 安全打开参数待 Q-017/LQ-007 冻结，本轮不添加可执行 URI 示例。Word 格式文档可能含宏/外链，禁止承诺无风险、自动开启宏或关闭保护。进程创建不等于文档已打开，无可靠网页回传。

- 本轮仅规划，不创建启动器源码、安装包、注册表项或协议关联。

## 2. 本机设置与双重目录绑定

- 用户在启动器中选择并确认本机 IQANdesign 程序；不得接受网页/项目 JSON 提供的可执行程序、工作目录或自定义参数模板。
- 按网页项目的稳定 ID，在本机显式绑定允许的工程根目录；用户可查看、重绑和解除绑定，不将项目零件号直接当唯一目录映射键。
- 浏览器授权句柄与启动器绑定独立。启动器不直接读取浏览器 Dexie.js，不将浏览器输入路径当授权，也不假设两处绑定自动一致；确认界面必须展示最终实际文件路径。
- 项目 JSON 恢复不恢复本机信任。新设备/新项目 ID 必须在启动器重新登记；同设备已登记 ID 也不能免除每次操作确认。相同 ID 不是身份认证。
- 本机设置独立保存在当前用户配置位置，与网页备份分开。文件缺失/目录移动要明确提示，不自动搜索其他目录或回退到同名文件。

### 后续目录完整路径交接需求（未冻结）

- 2026-10-30 用户确认：Web 当前只显示/复制目录名，Launcher 实现后继续实现两类目录完整路径展示/复制，见 SPEC-01-AC-11、Launcher LSP-02-AC-07。
- 完整路径来自用户显式确认的本机绑定，而非浏览器句柄推导；按稳定项目 ID 与工程/软件对比文档角色关联。浏览器句柄与本机绑定仍独立，同名不代表同目录，路径信息不授予浏览器读取权限或启动信任。
- Q-020：如何将经确认路径安全交给对应网页项目/角色？须确定交接方式、用户确认、来源/请求关联、防重放与过期、重绑/解除失效、存储和隐私边界。Launcher 已实现本身不等于网页具备回传能力；本增强依赖契约冻结及两端联调，不擅自采用 localhost、常驻服务、云回调或新 URL 参数。
- 当前 `open`/`compare` 仍单向激活、无可靠执行结果回传；此处仅登记后续路径信息交接需求，未发布新协议字段、操作或成功回传承诺。未解决前保留目录名降级。

## 3. 激活协议契约

建议协议名为 `iqanarchive`，发布前确认并冻结；它是本产品自定义协议，不是 IQANdesign 自带协议。

概念请求：

```text
iqanarchive://open?v=1&project=<encoded-id>&file=<encoded-relative-path>
iqanarchive://compare?v=1&project=<encoded-id>&fileA=<encoded-relative-path>&fileB=<encoded-relative-path>
```

- 协议版本、项目 ID、操作和相对路径为结构化数据；实际字段语法、编码、长度/数量上限见 Q-017，示例不是已发布协议。
- 参数解码按统一规则执行一次；拒绝畸形编码、重复关键字段、未知操作、未知协议版本及超限请求，不容许模糊解析。
- `open` 只接受一个文件，`compare` 只接受有序两个文件；比较按 `[fileA, "-diff", fileB]` 构造受限参数。
- 相对路径不能是绝对路径、盘符路径、UNC、设备路径、备用数据流、包含空字符或越界的 `..`。规范化后检查路径边界及 junction/symlink/reparse point 的最终目标；仅字符串前缀比较不足以保证位于根目录。
- 仅接受经本机版本验证的工程扩展名；用户可管理 `.idax/.idsx/.idvx` 元数据不等于已验证三者的打开/对比能力。
- URI 不携带二进制、令牌、命令、EXE 路径或任意回调 URL。编码只是传输，不是加密；不记录完整敏感 URI到分析服务。

## 4. 信任与执行流程

1. Windows 收到协议请求后按注册关联激活启动器；浏览器可能先要求用户确认打开外部应用。
2. 启动器把 URI 当不可信输入校验，读取本机项目映射及程序设置，定位文件。
3. 显示本机确认界面：操作、项目 ID、IQANdesign 路径、实际工程路径；对比明确 A/B 顺序。用户取消则不创建 IQANdesign 进程。
4. 确认后重新检查路径及存在性，使用平台进程 API 的参数列表，不通过 cmd/PowerShell，不使用 shell 字符串拼接；单文件参数方式须实机验证。
5. 本机提示进程创建成功或具体失败；不能把进程创建/退出误称工程加载完成或比较完成。显示与操作相关的错误，不隐藏失败。
6. 启动器完成本次工作后可退出，不要求随 IQANdesign 常驻；重复激活/并发请求处理方式需受控，不允许后台排队自动执行未确认请求。

任何网站或本地程序都可能触发协议。启动器不能验证请求真实来自哪个网页，URI 中的 `origin`、站点 URL、项目 ID 或请求 ID 都不能作为身份认证。**初版每次操作必须本机确认**，不得仅靠自报来源白名单或浏览器外部应用确认替代本机校验。防止请求洪泛、并发弹窗的实现策略随 Q-017 定案。

网页不接收可靠回传。本机错误留在本机显示；不为了状态返回临时引入 localhost 服务、浏览器扩展、云端回调或 JSONP。

## 5. 安装、更新与卸载

- 需用户显式安装并同意协议注册；优先评估当前用户安装，企业策略是否允许需实测，不以管理员权限作默认前提。
- 注册时可靠引用启动器本身并处理路径空格和参数边界，防止协议内容成为任意命令；C#/.NET/WinForms 与自包含方向已定，具体安装器/注册机制未定，不在 SPEC 给出未经验证的注册命令。
- 安装后可在本机检查配置、用固定样例验证激活；网站不声称可靠检测安装状态。
- 更新/修复需保留或显式迁移本机配置，兼容协议版本；签名、分发位置和版本展示见 Q-016。先不引入自动更新。
- 卸载只移除本产品拥有的关联/文件；若协议已被其他应用接管不得删除其关联；是否保留用户配置给出明确选项。不删除工程文件、软件对比文档或浏览器数据。

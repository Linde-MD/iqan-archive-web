## 目标与边界

- **目标用户与场景**：IQANdesign 工程维护者需要按项目整理 IQAN 工程版本，并通览、编辑项目版本分支图。
- **目标闭环**：管理项目及其软件零件号；根据受支持的文件名提取零件号/版本；在图上浏览并编辑版本节点、分支与合并。
- **核心范围**：多项目；文件名解析；统一全局归档根目录授权、项目名派生工程/文档子目录及按项目独立扫描；根目录中的单项目 JSON 配置导入/导出；Dexie.js 持久化；Git Graph 纵向版本图、局部滚动/缩放、节点/父边/分支/合并操作；任务看板、可配置 Status/Type/priority、assignee/日期/评论字段、任务聚合/全部版本两模式及双向定位；放行及全祖先传播。展开的版本节点常显版本号，不显示零件号；改动说明通过节点文本和详情可访问。
- **软件对比文档**：用于存放软件版本对比说明；目录和功能以业务用途命名，Word 仅为首版 `.doc/.docx` 格式及后续本机打开程序，本次不扩展格式范围。
- **已确认文件边界**：工程与文档分别保留在统一归档根目录下 `<项目名>_iqan_project_files` 和 `<项目名>_software_changes_docs` 子目录；每项目独立扫描。JSON 文件默认直接在共享根目录读写，只备份项目元数据与图/任务状态，不携带原文件、文件路径或根目录授权；共享根目录不可用时不回退本地根目录。恢复后沿用本机根句柄（若有）并按项目名扫描，不自动创建缺失目录。
- **任务外部关联**：任务可有可无外部 Task ID。用户手工维护 1–16 位纯数字编号，同项目内唯一，代码字段为 `externalTaskId`，与系统内部 `Task.id` 及节点引用 `taskId` 明确区分；数据模型不绑定 Loop，方便迁移至其他任务系统。外部 Task ID 随配置备份；首版不提供外部链接、登录、读取或同步，不声称已验证编号存在或权限。
- **对比需求**：选中两个版本节点后右键对比；SPEC-04 的显式双选、自动文件复检、唯一匹配直接请求及异常面板已实现，使用 IQANdesign 的 `-diff` 外部查看器，不在网页解析工程内容。Launcher 核心和内部包已可用；正式站点全链路及兼容/异常验收仍需补齐。
- **可选本地能力**：用户安装 Windows 自定义协议启动器后可请求单文件打开和双文件对比。Windows 按需激活，本机校验/确认后调用 IQANdesign；没有本地 HTTP/常驻服务。工程 URI v1 已冻结，协议解析、安装发布和 IQANdesign 兼容仍未验收；未安装也能使用网页核心功能。
- **尚未完成的设计/实现**：独立任务看板及 Status/Type/priority 选项维护、assignee/日期/评论规则、跨页跳转、JSON 冲突/限额、正式 IQANdesign/Word 端到端验收；软件对比文档版本匹配为扫描临时派生，版本节点图标与多份选择正在实现。文档关联不写入数据库或 JSON，未来手工/版本对关联需另行确认。
- **本轮不假定**：解析/修改 IQAN 二进制、Web 内部 diff 引擎、内容合并、与 Git 互操作、云端协作、自动生成软件对比文档。手册展示的外部对比能力与本工具能启动它是两个条件。

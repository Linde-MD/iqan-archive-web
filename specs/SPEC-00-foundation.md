## 1. 目标

为后续项目登记、文件名解析和版本图建立一致的应用边界、领域数据契约草案与实现顺序。本阶段不实现业务代码。

## 2. 范围

- 包含：核对仓库现状；提出空白 Web 应用技术建议；定义项目、版本节点、图关系、分支和文件元数据的职责边界。
- 不包含：创建应用脚手架、安装依赖、实现后端、登录、协作或 IQAN 二进制解析。
- 已确认：仓库优先静态 WebApp，沿用 npm；用户要按项目维护版本图。
- 建议：空白应用可评估 Vue 3 + TypeScript + Vite；领域模型应避免把人类可读版本号直接当作唯一实体 ID。
- 已确认补充：Dexie.js 保存本地配置；单项目 JSON 可导出/恢复；工程与 Word 文件保留原目录，恢复后重绑；静态网页通过授权选择目录，不直接运行 EXE。
- 第四轮确定 GitHub Pages＋可选 Windows 协议启动器：网页不直接执行进程，启动器不提供 HTTP 服务；本机授权与浏览器句柄独立，未安装不阻塞核心应用。
- 未确认：项目编号唯一性、重复版本、分支/合并细节、任务复杂分组、放行后修改及共享方式。

## 3. 功能与交互规则

本 SPEC 是基础设计框架，无用户界面要求。

建议的领域实体草案（Q-001 已解决；需继续结合 Q-002、Q-003、Q-006、Q-010、Q-011 修订）：

- **项目**：稳定内部 ID、显示名称（待决定）、软件零件号。
- **版本节点**：稳定内部 ID、显示版本号、改动说明；可关联一个或多个来源文件元数据。版本号可能重复，不能先验作为唯一键。
- **文件元数据**：原文件名、解析出的零件号/版本号/候选日期/扩展名、解析状态和原目录内相对引用。不保存二进制对象；JSON 配置不携带真实文件。
- **图关系**：显式记录节点间的父子关系；分支名称附着在分支头上。多父合并、移动头节点及循环保护需由 Q-003 决定。
- **分支**：稳定 ID、项目 ID、名称、头节点引用、可编辑说明及颜色。名称与颜色需求已确认；说明字段为建议，完整字段待细化。
- **任务**：稳定 ID、项目 ID、名称；说明字段为建议。版本节点持有可空 `taskId`，只引用同项目任务；一个任务可含多个节点。任务聚合是视图，不增删实际版本边。
- **放行**：每个真实节点有已放行/未放行状态。放行集合为目标节点加所有父边可达祖先；包含合并来源，不因任务折叠/分支颜色改变。建议另外保存显式放行目标用于解释来源；审计字段及撤销策略未定。
- **目录配置与绑定**：每项目分别保存工程目录、Word 目录地址提示及文件相对定位配置。用户授权的目录句柄/权限属于本机绑定层，不是可移植 JSON 配置；不把输入地址当读取授权。

### 任务与 Loop 卡片的关联结构（REQ-020）

用户确认首版仅手工填写 Loop 看板卡片 ID，且同一项目内唯一；不提供卡片链接、Loop 登录、API 读取或同步。以下为任务结构设计草案，不代表已有类型或数据库：

| 字段 | 草案类型/约束 | 用途 |
| --- | --- | --- |
| `id` | 稳定内部 ID | 节点 `taskId` 的引用目标，不使用 Loop ID 替代 |
| `projectId` | 稳定项目 ID | 限制节点关联与外部编号唯一性的项目范围 |
| `name` | 字符串 | 本地任务名称，不声称自动匹配 Loop 卡片标题 |
| `loopId` | `string \| null` | 用户录入的卡片 ID，如 `1479-1`；null 表示未关联，非空值同项目唯一 |

- 不强制所有任务来自 Loop；无关联的任务仍可使用。`loopId` 保留字符串语义，不数值化、不拆成父子任务编号，不从示例推导正式正则。
- 更改/清空 `loopId` 仅编辑本地关联元数据，不修改内部任务 ID、节点 `taskId`、图关系、任务归属或放行状态，也不修改远端 Loop 卡片。
- 不同项目可使用相同 Loop ID；同项目冲突须拒绝保存并指出已有任务，不按编号自动合并或重定向节点。多个未关联任务的 null 不视为重复。
- 唯一性必须在领域命令和持久化层一致保证，不仅靠表单预检查；最终归一化/索引规则依 Q-018 冻结。建议首尾去空白、空值转 null、非空字符串精确比较；这是待确认方案，不是已确认语法。
- 关联只是用户维护的编号映射，不存远端认证信息，也不能验证卡片存在、最新状态或访问权限。展示归 SPEC-02，持久化/迁移归 SPEC-03。

## 4. 必要接口与数据

下列仅为责任边界，不是定稿 API：

| 边界 | 建议输入/输出 | 未决项 |
| --- | --- | --- |
| 项目服务 | 创建/读取/更新/删除项目元数据；列出项目 | 零件号唯一性、删除项目的数据影响 |
| 文件名解析 | 输入文件名；输出候选零件号、版本号、日期、扩展名和解析错误 | 完整语法与扩展名策略见 Q-005 |
| 版本图领域层 | 节点和显式关系；输出可验证的无环图、分支头信息 | 合并、分支与删除语义见 Q-003/Q-004 |
| 存储适配层 | Dexie.js 异步事务、版本迁移和明确错误 | 只保存配置/元数据；JSON 冲突与限额见 Q-012，协作见 Q-007 |
| 配置导入导出 | 单项目配置快照与版本化 JSON | 所有实体引用需闭合；不含二进制、目录授权或命令 |
| 任务视图投影 | 真实图和任务关联 → 聚合/全展开图 | 跨分支/非连续分组见 Q-010；不修改真实关系 |
| 任务 Loop 关联 | 内部 task ID、project ID、可空 Loop ID → 更新结果或明确字段/唯一性冲突 | 仅本地手工编号；完整语法及归一化见 Q-018，不访问 Loop |
| 放行领域命令 | 节点 ID → 目标与全祖先集合、状态变更 | 原子保存、去重、非法图拒绝；撤销/改链见 Q-011 |
| 文件访问/启动请求 | 浏览器授权目录、稳定项目 ID 与相对文件引用 → 受限协议请求 | 本机配置/确认见 SPEC-05；网页不能可靠检测安装或启动结果，JSON 不恢复信任 |
| 对比请求（临时状态） | 两个稳定节点 ID、有序 A/B 与精确文件引用 → 对比预览/明确能力错误 | [SPEC-04](./SPEC-04-iqandesign-integration.md)；与领域写操作隔离，不序列化命令或持久化临时选择 |

存储不应依赖某个 UI 图形库的数据结构；画布坐标与领域关系应分开，并决定是否需要保存布局。

## 5. 异常与边界

| 条件 | 预期行为与用户反馈 | 恢复方式 |
| --- | --- | --- |
| 必需的项目字段未定 | 将字段标为待确认，不据建议阻塞文档生成。 | 后续补充后同步 SPEC-01。 |
| 数据保存能力或容量不足 | 实施时明确显示存储失败，不伪装保存成功。 | 提供重试、配置 JSON 导出或用户主动清理方案。 |
| 形成图循环或非法关系 | 领域层拒绝保存并报告冲突，不接受无效图。 | 依据 Q-003 定义修复交互。 |

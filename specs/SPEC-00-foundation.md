- 已确认：Vue 3 + TypeScript + Vite、npm、Dexie.js；内部实体使用独立 ID。第九轮澄清：文件名日期样式文本属于完整版本，不同完整版本是不同节点；只有相同完整版本才可多快照，磁盘修改时间不决定身份。
- 已确认补充：Dexie.js 保存本地配置；单项目 JSON 可导出/恢复；工程与软件对比文档保留原目录，恢复后重绑；静态网页通过授权选择目录，不直接运行 EXE。

## 3. 功能与交互规则

基础 UI 仅提供项目创建、列表、存储状态与能力边界提示，不显示伪造版本图或未实施操作按钮。

领域类型实现见 `src/domain/model.ts`，校验/命令见 `src/domain/graph.ts`：

- **项目**：稳定内部 ID、必填名称/零件号、兼容旧双目录提示字段、递增修订号。零件号非全局唯一键。
- **版本节点**：稳定内部 ID、同项目唯一完整版本号（含日期文本、去首尾空白、连续空格/Tab 归一、区分大小写）、说明、任务及放行时间；本地文件按当前扫描自动匹配，不从版本文本/修改时间推断关系。
- **文件匹配（2026-11-06 修订）**：文件名解析与当前扫描结果仅作会话派生状态，以当前项目零件号+完整版本匹配，不属于领域图或 JSON。数据库 v5 新增全局 `archiveRoots`，旧逐项目绑定表仅兼容保留；每个项目按名称解析工程/doc 子目录并各自扫描。登记只创建缺失节点，详见 SPEC-01。
- **图关系**：显式无环父子边；新版本仅推进明确目标分支（包含当前头作为父节点），合并至少双父，保留源分支头，不合并文件。
- **分支**：稳定 ID、项目 ID、名称、头节点引用、可编辑说明及颜色。名称与颜色需求已确认；说明字段为建议，完整字段待细化。
- **任务**：稳定内部 ID、项目 ID、必填名称、说明、可空外部 Task ID，以及可空 Status/Type 选项引用和看板排序。节点最多一个同项目任务；允许跨分支/不连续分组，投影保留所有真实边和端点映射/分支头摘要。删除任务只解除关联；初始全部版本，展开状态不持久化。Status/Type 选项按项目维护，选项删除会清空使用它的任务字段。
- **看板任务字段扩展（REQ-036，待确认）**：任务将增加 assignee、开始/截止日期、priority 选项引用及可新增/修改的评论集合。assignee 的存储类型、日期语义、priority 初始/默认/删除规则和评论作者/时间/内容/编辑历史由 SPEC-07 的 Q-022–Q-025 确认；不得据此引入账号、远端人员目录或同步。确认后的字段由 Dexie v6 / JSON schemaVersion 4 首次纳入，若已发布则另行版本迁移。
- **放行**：目标加所有可达祖先，记录首次放行时间，不记人员，重复操作幂等。有子节点的已放行节点撤销时，经确认后在原子事务内撤销目标及全部后代，不回撤祖先；已放行版本号锁定，可编辑说明与任务。直接重设已放行版本的父节点时，保留该节点原放行时间，并按新父边递归补齐未放行祖先；旧祖先不自动撤销。删除重连和批量关系命令仍不得修改已放行子节点的父边。本地文件独立维护、不锁定。
- **目录配置与绑定**：仅保存一个全局归档根目录句柄；每项目工程和软件对比文档子目录由项目名及固定后缀派生，并分别扫描。根句柄/权限/路径不属于可移植 JSON；旧逐项目 `directoryBindings` 和提示字段仅兼容保留，不作为当前授权来源。

### 任务与外部 Task ID 的关联结构（REQ-020）

用户确认任务可手工维护外部 Task ID；编号为 1–16 位 ASCII 数字，同项目唯一，去首尾空白、空值转 null，保留为字符串且允许前导零。数据模型与界面不绑定 Loop，以支持未来迁移到其他任务管理系统；首版不提供外部链接、登录、API 或同步。2026-11-03 用户将原先的任意文本规则改为纯数字；2026-11-03 用户要求将字段命名改为 Task ID，避免与系统内部 ID 混淆。既有 `loopId` 数字值保留并迁移字段名，非数字值不转换且读取/导入时明确拒绝。

旧字段的一次性迁移已完成；当前实现不再迁移或接受 `loopId`，只支持 `externalTaskId`。

| 字段 | 草案类型/约束 | 用途 |
| --- | --- | --- |
| `id` | 稳定内部 ID | 节点 `taskId` 的引用目标，不使用外部 Task ID 替代 |
| `projectId` | 稳定项目 ID | 限制节点关联与外部编号唯一性的项目范围 |
| `name` | 字符串 | 本地任务名称，不声称自动匹配 Loop 卡片标题 |
| `externalTaskId` | `string \| null` | 用户录入的 1–16 位数字外部任务编号，如 `1`、`2`、`3`；null 表示未关联，非空值同项目唯一 |
| `statusOptionId` | `string \| null` | 项目 Status 选项的稳定引用；null 进入“未分组”泳道 |
| `typeOptionId` | `string \| null` | 项目 Type 选项的稳定引用；null 表示未设置 |
| `sortOrder` | 有序数值 | 看板泳道内任务卡片的持久顺序 |

REQ-036 的看板字段模型待 Q-022–Q-025 确认：assignee 表示/引用、开始与截止日期类型、`priorityOptionId` 及项目 priority 选项、评论实体元数据。确认前不视为本基础阶段已实现或已验收；具体持久化与导入导出归 SPEC-07 / SPEC-03。

项目还保存有序的 Status/Type 选项列表，每个选项有稳定 ID 与可编辑名称。重命名保留引用；删除时确认并清空使用该选项的任务字段。新建任务默认 Status 为 `Backlog`，Type 可不选。

- 不强制所有任务来自 Loop 或任何单一系统；无外部关联的任务仍可使用。`externalTaskId` 保留字符串语义，不数值化、不拆成父子任务编号；正式校验为 1–16 位 ASCII 数字。
- 更改/清空 `externalTaskId` 仅编辑本地关联元数据，不修改内部任务 ID、节点 `taskId`、图关系、任务归属或放行状态，也不修改外部任务系统记录。
- 编号仅允许 ASCII 数字 `0`–`9`，长度 1–16 位；输入首尾空白会去除，保留前导零且不数值化。其他字符（含连字符、字母和全角数字）拒绝。空值转为 null。
- 不同项目可使用相同外部 Task ID；同项目冲突须拒绝保存并指出已有任务，不按编号自动合并或重定向节点。多个未关联任务的 null 不视为重复。
- 唯一性在领域与 Dexie `[projectId+externalTaskId]` 复合唯一索引一致保证；null 不形成唯一索引项，允许多个未关联任务。Q-018 的最大长度沿用第八轮确认值；2026-11-03 用户确认编号格式仅为数字。
- 外部 Task ID 只是用户维护的编号映射，不存远端认证信息，也不能验证记录存在、最新状态或访问权限。展示归 SPEC-02，持久化/迁移归 SPEC-03。

### 删除与存储契约

- `planDeletion` 提议子节点用被删节点全部父边替换、保留其他父边并去重；根删除后子节点可成根。可手改，提交须无环、同项目、无悬空；受影响分支须明确指定新头或删除分支记录。
- `applyDeletion` 不删除磁盘文件；只清除节点及相关边。已放行节点无论是否叶子均需二次确认并输入版本号；删除重连不能改已放行子节点父边。直接设置父节点的已放行版本例外及 UI 二次弹窗归 SPEC-02，基础命令要求确认凭据。
- 存储在同一 Dexie 事务中读取当前快照、验证期望修订、执行变更并跨表保存；旧标签页冲突明确拒绝，不静默覆盖。保存失败传播至 UI 错误区域，不吞掉异常。
- 第八轮首次 schema v1；v2 新增独立本机绑定表、检查版本归一化碰撞；v3 移除旧文件表；v4 的任务唯一索引使用 `externalTaskId`；当前 v5 增加全局根目录句柄。看板数据契约目标为数据库 v6、配置快照 schemaVersion 4；迁移为现有任务增加空 Status/Type 引用和确定性泳道顺序，并为项目安装默认选项，仍排除文件/句柄/二进制/命令/临时选择。

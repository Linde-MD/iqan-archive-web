# SPEC-08 可信小团队本地协作

- 规格状态：可实施（分阶段）
- 实施状态：A 后端基础预览已实现并通过本机验证；B/C/D 尚未完成
- 来源：2026-11-16 用户确认仅有共享目录，采用 Node.js/TypeScript + Access；首次初始化设置 admin 密码

## 1. 边界与阶段

每人以当前 Windows 用户运行本机服务，仅监听 `127.0.0.1`；多个服务访问同一个稳定 SMB UNC 路径中的 Access `.mdb/.accdb`。ODBC 建库接口实测生成 MDB，因此自动建库仅创建真实 MDB；ACCDB 需先在 Access 中创建空库，再初始化表。禁止将 MDB 改后缀伪装 ACCDB。不支持将 OneDrive/SharePoint 同步目录当数据库，不支持共享 SQLite，不引入云端服务。成员拥有数据库文件权限，因此账号只是可信客户端内的权限和防误操作，不保证防篡改或成员间强隔离。

| 阶段 | 交付与依赖 | 状态 |
| --- | --- | --- |
| A | 独立 `iqan-archive-server`：Access 原子提交/修订、账号/会话、项目快照 API、JSON 迁移入口、配置/启动/发行及自动测试；依赖现有领域与 JSON v7 契约 | 已实现；本机 MDB 与发行包验证通过，非正式上线验收 |
| B | 前端存储适配、连接/登录/用户管理、草稿与冲突、轮询刷新、原有 JSON UI 接入；依赖 A 的 API | 先实施本机端口设置/健康检测，其他未开始 |
| C | Launcher 受限服务启动、版本检查及正式 Pages→本机连接/权限验收；依赖 A 的固定安装约定、B 的连接 UI | 未开始 |
| D | 真实 SMB 双机故障/恢复、备份维护、混合版本拒绝、正式发布；依赖 A/B/C | 待环境验收 |

阶段 A 完成不代表现有网页已经切换到共享数据库。不自动迁移或删除 IndexedDB；B 阶段必须由用户明确选择权威数据源，失败不回退本地写入。

## 2. 后端数据与事务

- 复用前端领域校验，不另写一套放行/图合法性规则；构建时捆绑领域源码，不要求用户机器安装前端源码。
- Access 采用版本化记录表：项目以整个 JSON v7 聚合保存至 Long Text，保留项目/节点/任务稳定 ID。首期沿用当前整项目读写事务粒度，不假装已经提供 SQL 跨项目实体分析。
- 项目 revision 通过数据库事务中的条件更新裁决；并发旧版本写入返回 409。请求幂等记录与业务变更同事务提交；相同请求标识但不同内容拒绝。
- 原始 SQL、文件路径、数据库连接串不接受 HTTP 输入；参数化数据库命令。真实 Access 文件由本机命令行显式创建，网络请求不能创建或切换数据库。
- 所有 HTTP 写入均有大小/字段/图结构限制。最大项目快照继续为 20 MiB / 100,000 实体。初期无离线编辑或自动合并。
- 导入只允许管理员，新增/覆盖显式区分，覆盖必须匹配预期 revision；项目 JSON 不含用户、密码、会话、目录句柄或设备路径。既有导入 UI 的目标预览与身份重映射归 B。

## 3. 账号与本机边界

- 首次初始化仅由本机 CLI 完成；数据库事务保证 bootstrap 标记与唯一 admin 同时创建，不设通用密码、不在命令参数/日志中记录密码。
- admin 创建其他成员，设置初始密码并强制首次修改。成员可改密码、邮箱、显示名和受限头像。邮箱仅是联系字段，不声称验证或自动发邮件。
- 密码使用随机盐 scrypt；会话随机令牌仅返回给调用者一次，库内保存令牌摘要。默认会话 12 小时，记住登录 30 天；退出删除会话，密码修改/重置及停用通过用户认证版本撤销已有会话。
- 管理权限在服务端验证；成员不能创建/停用/重置其他账号。初始 admin 不能被停用。
- 仅允许配置的精确 Web origin；Host 固定回环地址与端口。除健康检查外要求 origin，写入要求 JSON；所有业务 API 要求 Bearer 会话。CORS 不是认证，不使用跨站 Cookie。
- 限流、请求超时、清晰错误、无敏感响应缓存。服务错误不会伪装空项目或保存成功。API/数据库不兼容时拒绝运行。
- B 阶段不把密码/令牌放 localStorage；记住登录的设备端安全存储方案在 B 实施前确定。

## 4. 本地发行与后续约束

- Node.js 自带 HTTP/crypto，通过 `koffi` 调用 Windows ODBC 宽字符 API，显式参数绑定、不注册 DSN。通用 `odbc` npm 包实测依赖 Access 不支持的 SQLDescribeParam，故不使用；不拼接业务值到 SQL。数据库工作进程独立且有超时，避免原生阻塞主 HTTP 进程。用户在本机脚本策略阻止 OleDb 桥后明确确认改用原生 ODBC；不修改/绕过 PowerShell 策略，不执行 PowerShell 或网页传入脚本。
- 首期限定 x64 Node/EXE 与 x64 Access ODBC 驱动；缺驱动明确失败。原生依赖随发行目录提供，EXE 不代表单文件或无系统依赖，公司应用控制须实机验证。
- 配置在本机；EXE 无参数（双击）默认执行 `serve` 并读取 EXE 同目录的 `config.json`，不依赖启动工作目录；源码无参数从当前目录读取。各命令保留 `--config` 显式覆盖。发行包只包含待修改的配置模板，不打包维护者本机配置。双击启动失败时在交互终端保留错误、按回车退出；正常运行保留控制台，Ctrl+C/关闭窗口停止，不安装后台服务。不自动创建库、管理员或缺失共享路径，不复制活跃数据库充当一致性备份。
- 网页顶栏提供“本机后端”设置：只编辑 1024–65535 的整数端口（默认 47831），地址固定 `http://127.0.0.1`。端口保存在本机 Dexie v13 的独立 `backendSettings` 表，v12 升级只新增空表，不改已有项目或根目录；不进入项目 JSON。保存与检测分离，明确未检测/检测中/服务可用或失败；检测有超时并验证产品、API/DB 版本与初始化状态。失败提示服务、端口、Origin 和浏览器权限检查，不把网络失败推断为服务未安装。当前检测成功只代表检测时服务可用，不代表登录或项目已迁往 Access。
- Launcher 未来只启动本机预设的受限服务，不接受任意命令/路径/端口；仅健康检查成功才显示已连接。连接失败不等于服务未启动。
- 当前正式前端仍可静态部署；Pages→localhost 需要验证浏览器本地网络权限、CORS、端口冲突和协议拒绝。

## 5. 验收

- A-01：真实 ACE 创建/重新打开数据库；Unicode、大于短文本的项目保存与 JSON 往返。
- A-02：两个独立服务对同一 revision 并发提交，只允许一个成功；多记录失败完整回滚；幂等重试不重复提交。
- A-03：首次初始化不可重复；错误密码拒绝；成员管理权限拒绝；首次改密前禁止业务操作；改密/停用撤销旧会话。
- A-04：来源/Host/内容类型/体积/字段/无效图/版本校验失败有明确错误；无任何固定初始密码。
- A-05：构建、类型检查、自动测试及 EXE 启动/健康检查；本地 Access 验证不能冒充 SMB 双机验证。
- B/C/D：网页登录、现有图/任务全流程、草稿保护、JSON UI、Launcher、正式 Pages、驱动矩阵、断网/掉电、备份恢复和维护窗口另行记录，不继承 A 的验收。

## 1. 边界与阶段

每人以当前 Windows 用户运行本机服务，仅监听 `127.0.0.1`；多个服务访问同一个稳定 SMB UNC 路径中的 Access `.mdb/.accdb`。ODBC 建库接口实测生成 MDB，因此自动建库仅创建真实 MDB；ACCDB 需先在 Access 中创建空库，再初始化表。禁止将 MDB 改后缀伪装 ACCDB。不支持将 OneDrive/SharePoint 同步目录当数据库，不支持共享 SQLite，不引入云端服务。成员拥有数据库文件权限，因此账号只是可信客户端内的权限和防误操作，不保证防篡改或成员间强隔离。

## 2. 后端数据与事务

- 复用前端领域校验，不另写一套放行/图合法性规则；构建时捆绑领域源码，不要求用户机器安装前端源码。
- 当前 Access schema 5 将项目元数据、节点、边、任务、分支分别存入 `ArchiveProjects`、`ArchiveNodes`、`ArchiveEdges`、`ArchiveTasks`、`ArchiveBranches`；账号、会话、提交回执等非项目记录留在 `ArchiveRecords`。每条项目/实体记录有独立行，载荷仍为 JSON Long Text；服务边界使用 JSON schemaVersion 8 完整图校验、备份及恢复。API v2 提供完整图和各实体集合读取，以及带 upsert/delete 的实体增量 PATCH；一个增量批次跨表原子提交，revision/CAS 仍以整项目为并发边界，不提供不同实体间的自动并发合并。
- 项目 revision 通过数据库事务中的条件更新裁决；并发旧版本写入返回 409。请求幂等记录与业务变更同事务提交；相同请求标识但不同内容拒绝。
- 原始 SQL、文件路径、数据库连接串不接受 HTTP 输入；参数化数据库命令。真实 Access 文件由本机命令行显式创建，网络请求不能创建或切换数据库。
- 所有 HTTP 写入均有大小/字段/图结构限制。最大项目快照继续为 20 MiB / 100,000 实体。原“无离线编辑”限制已由第 8 节的受限离线新增版本替代；仍不允许既有共享数据的离线修改或静默冲突合并。
- 导入只允许在线管理员，新增/覆盖显式区分，覆盖必须匹配预期 revision；Access 提交后用服务端实际快照更新本机 IndexedDB。项目 JSON 不含用户、密码、会话、目录句柄或设备路径；恢复不清空其他项目或账号。目标预览与身份重映射归 B，完整失败语义见第 8 节。

## 3. 账号与本机边界

- 首次初始化仅由本机 CLI 完成；数据库事务保证 bootstrap 标记与唯一 admin 同时创建，不设通用密码、不在命令参数/日志中记录密码。
- admin 创建其他成员，设置初始密码并强制首次修改。成员可改密码、邮箱、显示名和受限头像。邮箱仅是联系字段，不声称验证或自动发邮件。
- 密码使用随机盐 scrypt，允许 6–128 个字符，不要求复杂字符组合；会话随机令牌仅返回给调用者一次，库内保存令牌摘要。默认会话 12 小时，记住登录 30 天；退出删除会话，密码修改/重置及停用通过用户认证版本撤销已有会话。
- 管理权限在服务端验证；成员不能创建/停用/重置/删除其他账号。初始 admin 不能被停用或删除。成员删除及密码反馈增量见第 23 节。
- 任务负责人 ID 引用同一 Access 数据库内账号；仅启用的非 admin 成员可新分配。已停用成员的既有分配可保留并显示、清除或改派；目录 API 只返回非 admin 成员的 ID、用户名、显示名和停用状态，不返回邮箱等资料。
- 仅允许配置的精确 Web origin；Host 固定回环地址与端口。除健康检查外要求 origin，写入要求 JSON；所有业务 API 要求 Bearer 会话。CORS 不是认证，不使用跨站 Cookie。
- 限流、请求超时、清晰错误、无敏感响应缓存。服务错误不会伪装空项目或保存成功。API/数据库不兼容时拒绝运行。
- 勾选记住登录后仅在 IndexedDB 保存会话，不保存密码；不勾选时令牌仅留当前页面内存。退出移除会话、保留只读镜像和草稿，草稿仅原账号可同步。本机持久副本不构成成员之间的强隔离。

## 4. 本地发行与后续约束

- Node.js 自带 HTTP/crypto，通过 `koffi` 调用 Windows ODBC 宽字符 API，显式参数绑定、不注册 DSN。通用 `odbc` npm 包实测依赖 Access 不支持的 SQLDescribeParam，故不使用；不拼接业务值到 SQL。数据库工作进程独立且有超时，避免原生阻塞主 HTTP 进程。用户在本机脚本策略阻止 OleDb 桥后明确确认改用原生 ODBC；不修改/绕过 PowerShell 策略，不执行 PowerShell 或网页传入脚本。
- 首期限定 x64 Node/EXE 与 x64 Access ODBC 驱动；缺驱动明确失败。原生依赖随发行目录提供，EXE 不代表单文件或无系统依赖，公司应用控制须实机验证。
- 配置在本机；主 EXE 无参数（双击/Launcher）通过托盘宿主在后台执行 Node `serve`，读取 EXE 同目录的 `config.json`，不依赖启动工作目录，不弹出终端；源码无参数从当前目录读取。显式维护命令及 Console EXE 保留 `--config`，终端维护推荐直接调用 Console EXE。按用户确认，发行包默认配置原样取自 server 根目录 `config.json`，缺失则打包失败，不回退模板；不携带 `config.example.json`。配置含环境位置/来源，仅供授权团队分发。托盘状态窗口关闭只隐藏；显式退出等待请求和数据库正常结束，失败显示错误，不安装 Windows Service 或自动开机启动。不自动创建库、管理员或缺失共享路径，不复制活跃数据库充当一致性备份。
- 网页顶栏提供“本机后端”设置：只编辑 1024–65535 的整数端口（默认 47831），地址固定 `http://127.0.0.1`。端口保存在本机 Dexie v13 的独立 `backendSettings` 表，v12 升级只新增空表，不改已有项目或根目录；不进入项目 JSON。保存与检测分离，明确未检测/检测中/服务可用或失败；检测有超时并验证产品、API/DB 版本与初始化状态。失败提示服务、端口、Origin 和浏览器权限检查，不把网络失败推断为服务未安装。当前检测成功只代表检测时服务可用，不代表登录或项目已迁往 Access。
- Launcher 只接受固定的后端启动 URI，并从本机配置读取发行包 EXE；逐次显示路径并确认后，以无参数方式启动。网页不传任意命令/路径/端口，也不推断进程或服务成功；仅健康检查成功才显示已连接。连接失败不等于服务未启动。
- 当前正式前端仍可静态部署；Pages→localhost 需要验证浏览器本地网络权限、CORS、端口冲突和协议拒绝。

## 8. 同步副本、管理员恢复与离线版本增量（2026-11-16）

### 8.1 来源及已确认规则

- 用户要求保留 IndexedDB 持久化并与 Access 同步；保留 JSON 导出，将 JSON 导入改为 admin 专用的双库恢复入口。
- “离线”指无法访问本机后端/共享数据库，不依赖 `navigator.onLine` 判断。缓存可读不代表服务在线、会话有效或内容最新。
- 用户确认重新连通后**手动确认同步**；冲突保留草稿，提示修改版本号或父版本后重试，不自动覆盖同名版本。
- 用户确认离线仅可新增版本、修改这些版本自身及其父版本关系；既有版本、分支、任务和放行状态只读，不新增分支。
- 用户说明文件创建“不归后端管，沿用 Web/Launcher 逻辑”。本阶段不新增文件创建协议，不解析/生成 IQAN 二进制；工程文件不存入 Access 或 IndexedDB。
- 本次属于需求与契约增量；第 6、7 节验证仍只证明当时实现，不代表下述功能已经完成。

### 8.2 数据权威与设备副本

1. Access 是协作项目的权威来源；IndexedDB 保留完整的最近成功同步快照、服务端修订及同步时间，供本机浏览。在线保存须先取得服务端确认，再更新本机副本；不是两个可独立写入的主库。
2. 共享副本与离线新增版本草稿必须分开保存。刷新、轮询、重新登录、切换项目及应用重开不得覆盖草稿。页面将“共享已确认内容 + 本机待同步版本”投影展示，明确标记待同步状态及数量，不伪装为已共享。
3. 本机端口不是数据源身份。后端须提供稳定的数据库实例标识；缓存、待提交请求和离线草稿按实例/项目隔离，草稿记录创建账号稳定 ID。更换配置指向另一个 Access 库、不同账号登录或端口复用时，不得上传旧来源草稿或覆盖其副本。
4. 现有单人 IndexedDB 项目在切换协作模式时保留，不自动清空或上传，不仅按项目名/零件号就认作已同步。共享缓存和历史本地内容需明确区分；admin 通过恢复预览显式选择迁移目标。
5. Access 与浏览器 IndexedDB 无跨系统原子事务。服务端成功、本机更新失败时须显示“共享已提交，本机副本更新失败”，保留恢复信息并允许重拉；不能提示双库恢复完成，不能自动回滚/重发成另一次提交。
6. 在线写入结果不确定时保存原请求标识和原内容，先沿用原标识重试/确认结果；不能当成“离线新增”另行生成请求或重复节点。未决请求解决前，相关草稿保持不可更改的提交中状态。
7. 目录句柄、设备路径和端口继续仅留本机，不随服务端项目快照覆盖。缓存和草稿迁移须显式版本化，失败回滚且不得删除旧项目；具体版本号在实施迁移时确定，不提前声称当前 v13 已包含同步表。

### 8.3 连接、登录与离线权限

- 在线操作前验证会话、强制改密状态及服务端权限。连接检测成功不等于已登录；401/403 不冒充普通网络离线，失效会话须明确要求重新认证。
- 登录/连接状态与可写权限分开提示。在线但存在未确认提交时显示“已连接 · 提交待确认”，在图编辑、任务管理和工作区明确说明限制及原请求重试入口，不误报离线；在线但当前项目有待同步草稿时提示先预览/发布草稿，不影响其他无草稿项目。重试确认或同步完成后响应式解除对应限制，不清空原请求或绕过幂等保护。
- 工作台顶栏紧凑化，常规连接及同步成功不再占据页面提示区；断线、登录失效、写入限制、未确认提交、草稿冲突及刷新失败使用可关闭的悬浮提示，状态改变或同一错误恢复后再次发生时重新提示。账户入口保留连接状态与未确认提交标识，账户页保留同步规则、副本时间和浏览器草稿风险；权限及轮询行为不变。
- 悬浮提示验证：看板、协作与提示相关 77 项测试及生产构建通过；开发预览以模拟状态验证正常同步无提示、待确认和冲突可关闭并随状态变化重现、刷新失败恢复后再出现；375×812 和 812×375 下无页面横向溢出，关闭按钮为 44px。真实协作服务及完整键盘流程未验证。
- 2026-11-17 提示修正验证：14 项协作回归测试及生产构建通过，覆盖在线待确认请求保留原幂等键、重试成功后恢复可写，以及在线草稿与真正断线的限制区分。浏览器完整联调未完成，未代用户确认或清除实际待处理请求。
- 后端不可达时，已保存副本仍可浏览项目、图、任务和详情；无缓存时显示无可用离线数据，不显示“共享库为空”。
- 既有共享项目/节点/任务/分支及放行状态不可离线编辑或删除。禁用或隐藏对应控件并说明原因；仓库写入层同样拦截，包括快捷键、拖拽、撤销/重做、文件扫描批量登记及残留编辑面板的提交，不只依靠按钮禁用。
- 只允许在已有缓存项目中创建新的未放行版本，并修改其版本号、说明、现有任务引用及父版本关系；任务引用必须属于缓存项目，不允许通过版本编辑创建或修改任务。
- 新版本父引用可指向同项目缓存版本或本机待同步版本；不得改变任何既有共享节点的父边、分支头或放行状态。选择目标分支不得隐式推进既有分支头；离线创建入口应明确这是待同步版本而非分支操作。
- 草稿持久化失败时明确提示“未保存”，保留表单输入。关闭/刷新后应恢复已成功保存的草稿；本地持久化不等于永久备份。
- 已有在线未保存编辑遇到断线时保留输入但禁止写入共享既有内容；不将其静默变成允许同步的离线新增草稿。
- 后端恢复后先验证数据源和账号、拉取共享最新内容，保留离线草稿，显示可同步数量；不自动提交。
- 刷新成功仅报告共享副本已更新，不默认宣称存在离线草稿或要求手动同步；是否有待同步版本以实际草稿数量及同步入口为准，零草稿不显示虚假的同步要求。
- 此阶段保证后端不可达时的已加载网页和可取得前端资源的页面使用缓存；整站断网后首次打开、刷新和懒加载资源可用属于独立的前端离线资源缓存需求，未实现并断网验证前不能宣称支持。

### 8.4 手动同步与冲突

1. 用户主动发起同步，预览要发布的新增节点和父边，再明确确认。只将新增版本及其自身父关系提交，不能以离线整项目快照覆盖当前共享数据。
2. 服务端必须按当前账号/数据库实例、项目当前 revision 重新验证，不能相信客户端“新增”标签。新增版本为未放行、非测试中；不得借同步更新既有节点、任务、分支或放行字段。
3. 同一项目中相互依赖的草稿作为一次原子提交，按父子依赖验证完整引用、重复/归一化版本号、无循环、实体/体积上限；跨项目分别反馈结果，不承诺全库原子同步。
4. 预览后项目变更、共享同版本已存在、父节点/任务被删除或身份改变时返回明确冲突；保留全部未确认草稿及输入，展示原因，允许修改草稿版本号或父引用后重新预览。不得自动把同版本节点当作同一身份。
5. JSON 恢复或项目删除会使旧待同步草稿需重新校验；缺失或被替换的父节点不能按版本号猜测重连。项目已删除时不自动重建共享项目。
6. 提交请求 ID 和请求内容在网络发送前可靠保存，确认和业务写入复用服务端幂等事务。响应丢失、关闭页面后重开或重复点击均不得重复新增。
7. 只有确认 Access 接受该提交、取得实际共享快照并在本机事务内更新副本后，才能清除相应草稿的待同步标记。若共享已成功但本地失败，保留回执/草稿并显式显示可恢复状态，重试不重复提交。
8. 文件与元数据不是同一事务。同步不上传、改名或删除工程文件；网页原有扫描/重验/Launcher 流程独立处理，不能根据元数据成功就声称本地文件已创建。

### 8.5 JSON 双库恢复及导出

- JSON 继续是**单项目**业务快照，沿用 schema v3–v7 校验与 20 MiB/100,000 实体限制；不是整个 Access 文件的备份，不恢复账号、会话、其他项目、目录权限或工程文件。
- JSON 导入入口只对在线且已完成认证/强制改密的 admin 开放，确认时在服务端再次验证 admin。普通成员直接调用 API 同样拒绝；离线不得仅凭本机历史 admin 标识写入 IndexedDB。
- 恢复前拉取当前目标及 revision，预览覆盖范围、项目身份映射和破坏性影响；保留原有按零件号唯一匹配及显式新增规则，不自动猜测。已有草稿/提交中请求必须先明确处理，不得因恢复而静默删除。
- 确认后先在 Access 单项目事务内校验并提交恢复（覆盖 revision 递增，不回退为备份旧 revision），再读取实际共享结果并事务替换本机确认副本；本机目录句柄和其他项目不变。服务端失败不得先覆盖本地确认副本。
- Access 已恢复而读取/写入 IndexedDB 失败：明确说明共享恢复已成功、本机仍旧，保留原请求和恢复状态供重试；不能再次导入造成额外覆盖，也不能报告“全部完成”。
- 其他电脑通过后续刷新/轮询更新各自副本，恢复只保证当前客户端完成同步后才报告双库完成，不宣称远程所有设备同时完成。
- JSON 导出继续可用，离线可基于持久化副本导出；页面显示副本读取时间/来源。用户已确认：JSON v7 包含当前项目的待同步版本，导出前提醒数量和“尚未进入共享库”；admin 恢复时这些版本一并成为 Access 版本，不恢复原待同步标记。导出不清草稿、不充当上传回执。冲突导致快照非法时明确拒绝导出，保留草稿并提供修正入口，不静默只导出基线。

## 10. 请求延迟优化（2026-11-16）

- 用户反馈退出等待约 8 秒。原实现每个数据库操作启动一个工作进程/连接，health、users、logout 分别串行调用 2/3/4 次；同机隔离临时 MDB 基准为 3093/4841/5757 ms（前两项各 3 次中位数，退出单次），不访问用户配置或共享业务库。
- 复用每个服务的单个工作进程和原生 ODBC API；仅在同一 HTTP 请求内复用连接，作用域结束关闭连接，完成后才发送响应。尝试无限期复用连接时真实双进程测试读到旧缓存，已放弃；不靠 `PageTimeout=0` 或固定睡眠伪装一致性。Microsoft 文档也说明 [ACE/Jet 页缓存与提交有固有延迟](https://learn.microsoft.com/en-us/sql/odbc/microsoft/sqlsetconnectoption-access-driver)。
- 每个本机服务串行执行数据库请求作用域，跨服务仍依靠 Access 事务/CAS 和幂等记录裁决。保留每次会话/账号/权限与 schema 校验，无长期认证或项目快照缓存；同请求内复用成员列表读取、认证时读取的会话 revision；健康检查合并初始化状态读取。事务结束恢复自动提交。
- 内部通信改为有界二进制长度帧（单帧 64 MiB），工作消息队列最多 64 条等待/128 MiB、作用域队列最多 64 条、HTTP 并发仍为 8。工作调用含其队列等待最多 60 秒；超时/崩溃拒绝当前及待处理工作，后续才新建进程，不自动重放未知写入。CLI 初始化结束和正常服务关闭会清理工作进程；父进程退出时子进程从管道 EOF 退出。当时网页 API v1、数据库 schema 1 和 JSON v7 不变，无需迁移或重建；这是该阶段的历史状态，当前 schema 5 及迁移要求以第 17 节为准。

## 15. 增量写入响应

- 项目写入成功时，服务端回执可附带从 `baseRevision` 到 `revision` 的已提交差异，覆盖服务端最终实际修改的项目摘要、节点、边、任务及分支；放行传播、批量命令、撤销/重做和离线同步均不得只回显客户端请求而遗漏服务端产生的变更。
- 客户端仅在本机共享镜像的服务端修订等于 `baseRevision` 时应用差异，并校验合并后的完整快照；本地基线不匹配、旧回执无差异或差异过大时，必须回读完整项目图。显式刷新、初次加载、冲突恢复和管理员恢复的完整 JSON 行为不变。
- 不超过 1 MiB 的差异纳入幂等回执，使同一请求 ID 的重试可取得原提交差异；较大差异省略响应增量并按完整图回读，避免大型恢复内容无限增加长期回执。旧版本服务端回执保持兼容。
- 服务端仍按项目 revision/CAS 读取并校验完整图，增量响应只减少常规写入的网络响应与客户端回读，不承诺减少服务端完整图校验，也不提供跨实体并发自动合并。
- 验收：单任务修改仅上传任务实体并收到仅含该任务差异的响应，提交后不请求完整图；任务/节点/项目摘要变化都可正确更新本机镜像；状态传播、删除、分支顺序、撤销/重做及离线同步的差异完整；丢失响应使用原幂等键重试，旧回执/大差异/本地基线不匹配时完整图回退正确，任何失败均保留待确认请求。
